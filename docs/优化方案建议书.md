## 一、软件定位回顾

智聘云图是一款基于 **LLM 文档智能解析 + 六维度匹配引擎** 的智能招聘平台，三端协同（求职者 / 企业 / 管理员），核心卖点是 **AI 简历解析 → 能力图谱 → 精准人岗匹配 → 面试邀请全流程闭环**。

技术栈：Vue 3 + FastAPI + SQLAlchemy + GreatSQL + 灵犀大模型(ARK API) + WebSocket + ECharts

## 三、AI 智能能力增强（P0 — 差异化竞争力）

### 3.1 AI 简历优化建议

**目标用户**: 求职者

**现状**: 求职者上传简历后，系统仅做解析和结构化展示，缺乏对简历质量的深度分析。

**方案**:
- 简历详情页新增「AI 优化建议」按钮
- 调用 LLM 对简历进行多维度评估：
  - **技能描述**: 是否模糊（如"熟悉 Java"→建议改为"3 年 Java 后端开发经验，熟悉 Spring Boot 微服务架构"）
  - **项目经验**: STAR 法则完整性（情境/任务/行动/结果）
  - **整体完整性**: 缺失模块检测（教育背景、实习经历、自我评价等）
  - **关键词覆盖**: 与目标岗位热门关键词的匹配度
- 生成优化建议报告，每条建议附带「原文 → 建议改写」对比
- VIP 用户可一键应用建议改写

**演示价值**: 展示 LLM 的深度理解能力，不仅仅是解析，还能给出可执行的建议

**涉及改动**:
- 后端: `api/v1/resume.py` 新增 `POST /resumes/{id}/optimize` 接口
- 前端: `views/seeker/ResumeDetail.vue` 新增优化建议面板

---

### 3.2 AI 职位描述生成

**目标用户**: 企业招聘方

**现状**: 企业发布职位时需要手动填写所有字段，填写成本高，描述质量参差不齐。

**方案**:
- 发布职位页面新增「AI 生成」按钮
- 企业输入岗位名称 + 级别（初级/中级/高级）+ 核心技能（1-3 个关键词）
- LLM 自动生成：
  - 职位描述（岗位职责 3-5 条）
  - 任职要求（学历/经验/技能 3-5 条）
  - 加分项（2-3 条）
- 生成内容填入对应输入框，企业可二次编辑

**演示价值**: 展示 AI 赋能企业端，降低使用门槛

**涉及改动**:
- 后端: `api/v1/job.py` 新增 `POST /jobs/generate-description` 接口
- 前端: `views/employer/JobCreate.vue` 新增 AI 生成按钮和调用逻辑

---

### 3.3 面试问题智能生成

**目标用户**: 企业招聘方

**现状**: 企业发起面试邀请后，缺乏面试准备辅助工具。

**方案**:
- 候选人推荐列表/投递管理页面，点击候选人进入详情
- 新增「AI 面试题生成」按钮
- 系统根据候选人简历技能 + 职位要求，调用 LLM 生成面试问题清单：
  - **技术深度题** (3-5 题): 针对简历中提到的核心技能
  - **项目追问题** (2-3 题): 针对简历中的项目经历
  - **行为面试题** (2 题): 沟通协作、抗压能力等
  - **开放思考题** (1 题): 技术视野与学习能力
- 问题清单可导出为 PDF 或复制

**演示价值**: 展示 AI 在招聘全流程的深度参与

**涉及改动**:
- 后端: `api/v1/interview.py` 新增 `POST /interviews/questions` 接口
- 前端: 投递管理详情弹窗新增面试题生成面板

### 3.4 求职者竞争力分析

**目标用户**: 求职者

**现状**: 求职者不知道自己在同岗位候选人中的竞争力水平。

**方案**:
- 简历详情页新增「竞争力分析」Tab
- 系统统计同岗位（按职位类别匹配）所有候选人的数据：
  - **技能覆盖度百分位**: 你的技能数量 vs 同岗位中位数
  - **经验年限百分位**: 你的工作年限 vs 同岗位分布
  - **学历水平百分位**: 你的学历在同类候选人中的位置
  - **匹配得分百分位**: 你被推荐时的平均匹配分 vs 全体
- 雷达图展示五维竞争力，标注你所在的位置
- 给出提升建议（"你的 Python 技能在同岗位 TOP 30%，建议补充 Docker/K8s 提升竞争力"）

**演示价值**: 数据驱动 + AI 建议，展示平台的数据分析能力

**涉及改动**:
- 后端: `api/v1/resume.py` 新增 `GET /resumes/{id}/competitiveness` 接口
- 前端: `views/seeker/ResumeDetail.vue` 新增竞争力分析面板

## 四、用户体验优化（P1 — 演示效果直观）

### 4.1 投递状态实时追踪（时间轴）

**目标用户**: 求职者

**现状**: 投递记录只显示一个状态标签（待处理/已查看/面试邀请/已拒绝），求职者不清楚各阶段的时间节点。

**方案**:
- 投递记录列表点击某条记录，展开时间轴详情：
  ```
  ● 2026-08-01 14:30  投递成功
  │
  ● 2026-08-02 09:15  HR 已查看
  │
  ● 2026-08-03 10:00  面试邀请 (面试时间: 08-05 14:00)
  │
  ○ 待定              面试结果
  ```
- 每个节点显示时间、状态、操作方
- 进行中的节点高亮，未到达的节点灰色

**涉及改动**:
- 后端: `api/v1/application.py` 新增 `GET /applications/{id}/timeline` 接口
- 前端: `views/seeker/Applications.vue` 新增时间轴展开面板

### 4.2 企业端候选人对比

**目标用户**: 企业招聘方

**现状**: HR 查看候选人时只能逐个点开，无法横向对比。

**方案**:
- 候选人推荐列表增加「对比」复选框（最多选 3 人）
- 选中后底部浮出「开始对比」按钮
- 点击后弹出对比弹窗：
  ```
  │ 维度        │ 候选人A │ 候选人B │ 候选人C │
  │ 匹配得分    │   92    │   85    │   78    │
  │ 学历        │  本科   │  硕士   │  本科   │
  │ 工作年限    │   3年   │   5年   │   2年   │
  │ 核心技能    │ Python │  Java   │ Python  │
  │             │ Docker │ Spring  │  Vue    │
  │ 项目数      │    4    │    6    │    2    │
  │ 期望薪资    │  15K   │  20K    │  12K    │
  ```
- 匹配得分最高项高亮

**涉及改动**:
- 前端: `views/employer/Candidates.vue` 新增对比逻辑和弹窗
- 后端: 无需新增接口（复用已有数据）

**涉及改动**:

### 4.5 简历多版本管理

**目标用户**: 求职者

**现状**: 求职者只能上传一份简历，无法针对不同岗位使用不同简历。

**方案**:
- 简历管理页改为支持多份简历
- 每份简历可设置标签（如"后端开发版"、"全栈版"、"英文版"）
- 投递职位时选择使用哪份简历
- 默认简历标记（投递时不选则使用默认）

**涉及改动**:
- 后端: `Resume` 模型新增 `is_default` 字段，简历列表接口支持多条
- 前端: `views/seeker/ResumeManage.vue` 支持多简历切换
- 投递流程增加简历选择步骤

### 5.4 企业评价系统

**目标用户**: 求职者

**现状**: 求职者面试后无法对体验进行反馈，其他求职者也无法参考。

**方案**:

  - 面试体验 (1-5 星)

- 企业详情页展示综合评分和评价列表
- 评价匿名展示

**涉及改动**:
- 后端: 新增 `CompanyReview` 模型和对应 API
- 前端: 新增评价弹窗，职位详情页新增评价展示区

## 六、工程化与性能优化（P3）

### 6.1 全局搜索

**方案**:
- 顶部导航栏新增全局搜索框
- 根据当前角色搜索不同内容：
  - 求职者: 搜索职位名称 / 公司名
  - 企业: 搜索候选人姓名 / 技能
  - 管理员: 搜索用户 / 职位 / 企业名
- 搜索结果下拉展示，点击跳转对应页面
- 搜索框支持快捷键 `Ctrl+K` 唤起

**涉及改动**:
- 前端: 各 Layout 组件新增搜索框组件
- 后端: 新增 `GET /api/v1/search` 统一搜索接口

---

### 6.2 骨架屏 (Skeleton)

**方案**:
- 列表页加载时用骨架屏替代 `v-loading` 转圈
- 职位广场、候选人列表、投递记录等页面优先改造
- 使用 Element Plus 的 `el-skeleton` 组件

**涉及改动**:
- 前端: 各列表页组件替换加载状态

---

### 6.3 搜索防抖

**方案**:
- 所有搜索输入框增加 300ms debounce
- 使用 VueUse 的 `useDebounceFn` 或自定义指令
- 避免用户输入过程中频繁请求

**涉及改动**:
- 前端: 搜索相关组件统一添加防抖

---

### 6.4 暗黑模式

**方案**:
- 全站支持暗黑主题切换
- 顶部导航栏新增主题切换按钮（太阳/月亮图标）
- 使用 Element Plus 的暗黑模式 CSS 变量
- 用户偏好存储到 localStorage

**涉及改动**:
- 前端: `App.vue` 新增主题切换逻辑，`style.css` 新增暗黑变量
- 各组件检查硬编码颜色值并替换为 CSS 变量

## 九、验收标准

每个优化项完成后需满足：
1. 功能可用，无报错
2. UI 风格与现有系统一致（主题色 #1677ff，圆角卡片，hover 过渡）
3. 代码遵循项目约定（`res.data?.items || []`、`127.0.0.1:8001`、`600000ms` 超时等）
4. 涉及 LLM 的接口有 loading 状态和错误处理
5. 管理端新增图表有数据展示（必要时跑 seed 脚本）

# 智聘云图 · 注册与职位发布升级方案

> 版本: v1.0 | 日期: 2026-07-12 | 状态: 待实施

---

## 一、背景与目标

### 1.1 现状问题

| 模块 | 当前字段 | 问题 |
|------|---------|------|
| 求职者注册 | 用户名/手机/邮箱/密码/姓名/性别 | 缺少出生日期、工作经历，无法支持系统初步筛选 |
| 企业发布职位 | 职位/公司/城市/经验/学历/薪资/人数/描述 | 缺少福利待遇、工作时长、公司规模等关键信息 |
| 简历解析 | 姓名/性别/年龄/学历/学校/专业/工作年限 | 年龄由 AI 从简历文本提取，保留静态字段 |

### 1.2 升级目标

1. **求职者注册**: 增加出生日期 + 最近工作经历（可选），方便企业筛选
2. **职位发布**: 增加福利待遇 + 工作时长 + 公司规模，对标主流招聘网站
3. **系统初步筛选**: 基于新增字段实现自动匹配过滤，提升匹配精度

## 三、升级方案详细设计

### 3.1 数据库变更

#### 3.1.1 用户表 `sys_user` — 新增出生日期字段

```sql
ALTER TABLE sys_user ADD COLUMN birthday DATE NULL COMMENT '出生日期';
```

> `sys_user.birthday` 仅用于注册账号时收集求职者个人信息，方便企业按年龄段筛选。
> 简历上的年龄 (`resume.age`) 由 AI 从简历文本提取，两者独立，互不影响。

#### 3.1.2 简历表 `resume` — 年龄字段保留现状

> 简历上的年龄由 AI 从简历文本中提取并存储为静态 `age` 字段，不做改动。
> 原因: 用户可能上传他人简历（HR代投、猎头上传候选人），年龄应以简历原文为准，
> 不应由注册账号的出生日期动态计算。

```sql
-- resume 表无需新增 birthday 字段, age 字段保持现状
-- AI 解析时直接从简历文本提取年龄, 存入 resume.age
```

#### 3.1.3 新增工作经历表 `work_experience`

```sql
CREATE TABLE work_experience (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    resume_id   BIGINT NOT NULL COMMENT '所属简历ID',
    company     VARCHAR(128) NOT NULL COMMENT '公司名称',
    position    VARCHAR(128) NOT NULL COMMENT '职位名称',
    start_date  DATE NOT NULL COMMENT '入职时间',
    end_date    DATE NULL COMMENT '离职时间 (NULL=至今)',
    description TEXT NULL COMMENT '工作描述',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_we_resume (resume_id)
);
```

#### 3.1.4 职位表 `job` — 新增福利待遇/工作时长/公司规模

```sql
ALTER TABLE job ADD COLUMN work_hours    VARCHAR(64)  NULL COMMENT '工作时长 (如 9:00-18:00 / 弹性)';
ALTER TABLE job ADD COLUMN benefits      VARCHAR(512) NULL COMMENT '福利待遇 JSON数组 (如 ["五险一金","带薪年假","免费三餐"])';
ALTER TABLE job ADD COLUMN company_size  VARCHAR(32)  NULL COMMENT '公司规模 (如 100-499人)';
ALTER TABLE job ADD COLUMN industry      VARCHAR(64)  NULL COMMENT '公司行业';
```

### 3.2 后端 API 变更

#### 3.2.1 注册接口 `POST /auth/register`

**新增请求字段:**

```python
class RegisterRequest(BaseModel):
    # ... 原有字段 ...
    birthday: Optional[str] = None  # 新增: 出生日期 "1995-06-15"
    # 新增: 最近工作经历 (可选, 最多3条)
    work_experiences: Optional[list[WorkExperienceItem]] = None

class WorkExperienceItem(BaseModel):
    company: str = Field(..., max_length=128)
    position: str = Field(..., max_length=128)
    start_date: str = Field(..., pattern=r"^\d{4}-\d{2}$")  # "2023-01"
    end_date: Optional[str] = None  # "2025-06" 或 null (至今)
    description: Optional[str] = None
```

**注册流程变更:**
1. 创建 SysUser 时写入 `birthday`
2. 若提供 `work_experiences`，在 `work_experience` 表插入记录

#### 3.2.2 简历解析接口 — AI Prompt 升级

在豆包 AI 解析 Prompt 中增加:
- **年龄**: 直接从简历文本提取，存入 `resume.age`（保留现状，不做改动）
- **工作经历列表**: 提取公司/职位/起止时间/描述，写入 `work_experience` 表
- 不提取出生日期（简历上通常不写出生日期，且年龄应以简历原文为准）

#### 3.2.3 职位发布接口 `POST /jobs`

**新增请求字段:**

```python
class JobCreateParams:
    # ... 原有字段 ...
    work_hours: Optional[str] = None    # "9:00-18:00" / "弹性" / "996"
    benefits: Optional[list[str]] = None  # ["五险一金", "带薪年假", "免费三餐", "年终奖"]
    company_size: Optional[str] = None    # "100-499人"
    industry: Optional[str] = None        # "互联网"
```

#### 3.2.4 职位广场接口 `GET /jobs/plaza` — 新增筛选条件

```python
# 新增查询参数
benefits: str = Query("")          # 福利筛选 (逗号分隔)
company_size: str = Query("")      # 公司规模筛选
work_hours: str = Query("")        # 工作时长筛选
```

#### 3.2.5 匹配引擎 `match_service.py` — 新增筛选维度

在 `coarse_rank()` 中新增:
- **工作时长匹配**: 求职者期望 vs 岗位要求
- **福利匹配**: 岗位提供的福利标签作为加分项（不影响总分权重，仅展示）

### 3.3 前端页面变更

#### 3.3.1 注册页面 `Register.vue`

**个人用户新增字段:**

```
├── 出生日期 (el-date-picker, type="date", 必填)
├── 最近工作经历 (可选, 折叠面板)
│   ├── 公司名称 (el-input)
│   ├── 职位名称 (el-input)
│   ├── 起止时间 (el-date-picker, type="month")
│   ── 工作描述 (el-input textarea, 可选)

- 工作经历区域默认折叠，点击"添加工作经历"展开
- 支持"跳过"按钮，标注"(选填)"
- 出生日期使用 `el-date-picker` 日期选择器
- 保持与现有注册页一致的蓝紫渐变品牌风格

#### 3.3.2 职位发布页面 `JobCreate.vue`

**新增字段区域:**

```

├── 福利待遇 (多选标签)

- 福利筛选: 多选标签
- 公司规模筛选: 下拉选择
- 工作时长筛选: 下拉选择

### 3.4 系统初步筛选逻辑

基于新增字段，在匹配引擎中实现以下自动筛选:

| 筛选规则 | 逻辑 | 优先级 |
|---------|------|--------|
| 年龄筛选 | 使用简历上的 `resume.age`（AI从简历文本提取），对比岗位经验要求 | 高 |
| 工作经历匹配 | 最近工作经历的公司/职位与岗位关联度 | 中 |
| 福利匹配 | 岗位福利标签作为加分展示项 | 低(仅展示) |
| 工作时长匹配 | 求职者偏好 vs 岗位要求 | 中 |

## 五、注意事项

1. **向后兼容**: 所有新增字段均为 `nullable`，不影响现有数据和功能
2. **工作经历可选**: 用户可跳过工作经历填写，不影响注册流程
3. **AI 解析降级**: 若 AI 无法从简历中提取出生日期/工作经历，字段保持 NULL
4. **福利标签标准化**: 使用预定义标签列表，避免自由输入导致数据混乱
5. **性能**: 工作经历表按 `resume_id` 建索引，查询性能不受影响

## 六、预期效果

- **求职者**: 注册信息更完整，系统可基于出生日期+工作经历做初步筛选
- **招聘企业**: 职位信息更丰富（福利/时长/规模），吸引更多候选人
- **匹配精度**: 六维度匹配 + 新增筛选维度 → 匹配结果更精准
- **用户体验**: 对标主流招聘网站，降低用户学习成本

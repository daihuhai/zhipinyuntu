### 2.2 测试策略

#### 2.2.1 功能测试策略

采用 **基于需求的测试设计方法**，结合等价类划分、边界值分析、正交实验法和场景法，对每个功能模块进行系统性的测试设计。功能测试分为以下四个层次：

1. **单元功能测试**：验证单个功能点的输入输出正确性，确保每个原子操作符合预期行为。
2. **模块内集成测试**：验证同一模块内多个功能点的协同工作，确保数据流转和状态变更正确。
3. **跨模块集成测试**：验证模块间的接口调用和数据传递正确性，重点关注简历→匹配→投递→面试的核心业务流程。
4. **端到端用户场景测试**：模拟真实用户操作路径，覆盖完整的业务生命周期。

#### 2.2.2 集成测试策略

| 测试层次 | 集成方式 | 验证重点 | 工具 |
|----------|----------|----------|------|
| API集成 | HTTP接口调用 | 请求/响应正确性、状态码、错误处理 | Postman / pytest |
| 服务层集成 | 服务间RPC调用 | 服务协同、数据一致性 | 单元测试框架 |
| 数据库集成 | ORM操作验证 | 数据持久化、事务回滚、并发控制 | SQLAlchemy测试 |
| 前端集成 | 组件交互 | 组件生命周期、状态管理、路由跳转 | Vitest / Vue Test Utils |
| 端到端集成 | 完整业务流程 | 用户操作路径、页面跳转、数据联动 | Playwright |

#### 2.2.3 系统测试策略

| 测试类型 | 方法 | 评估指标 |
|----------|------|----------|
| 功能正确性 | 逐功能点验证 | 通过率 ≥ 98% |
| 业务流程 | 端到端场景执行 | 关键路径100%通过 |
| 数据一致性 | 前后端数据核对 | 数据完全一致 |

| 状态管理 | 状态流转验证 | 状态机规则100%覆盖 |

#### 2.2.4 验收测试策略

采用 **α测试 + β测试** 相结合的方式：

- **α测试**：项目团队内部完成，覆盖全部核心功能模块，验证系统功能完整性和稳定性。
- **β测试**：选取5家合作企业和50名求职者进行内测，收集真实使用反馈，重点验证用户体验和业务流程合理性。

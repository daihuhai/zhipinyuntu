# 智聘云图 系统升级方案

> 版本：v1.1 · 编制日期：2026-07-12
> 范围：安全性加固、性能优化、逻辑修正、功能扩展、前端体验提升
> 目标：将平台从「可用」提升至「可上线」水准，覆盖安全合规、响应速度、业务完整性与用户体验四大维度

---

## 一、问题总览

经全面审查，共识别 **28 项** 待优化点，按优先级分布如下：

| 优先级 | 维度 | 数量 | 说明 |
|--------|------|------|------|
| P0 紧急 | 安全性 | 5 | 可被直接利用的高危风险 |
| P1 高 | 逻辑/性能 | 8 | 影响数据正确性与响应速度 |
| P2 中 | 功能扩展 | 9 | 补齐招聘平台标配功能 |
| P3 低 | 前端体验 | 6 | 提升用户感知质量 |

## 二、安全性加固（P0）

### 2.1 JWT 密钥硬编码默认值

- **位置**：[config.py](file:///d:/智聘云图/backend/app/core/config.py#L22) `SECRET_KEY: str = "change-me"`
- **风险**：攻击者已知默认密钥即可伪造任意用户 JWT，实现越权登录（含管理员）
- **方案**：
  1. 启动时校验 `SECRET_KEY != "change-me"`，生产环境直接抛异常拒绝启动
  2. `.env.dev` 注入随机 64 字符密钥（`python -c "import secrets; print(secrets.token_urlsafe(48))"`）
  3. 增加密钥轮换机制：access_token 携带 `kid` 字段，支持多密钥并行验证

### 2.2 默认管理员弱密码

- **位置**：[main.py](file:///d:/智聘云图/backend/app/main.py#L50) `hash_password("admin123")`
- **风险**：自动化扫描脚本可在 1 分钟内爆破
- **方案**：
  1. 首次启动生成随机密码并打印到日志（仅一次）
  2. 或强制管理员首次登录修改密码
  3. 数据库默认密码 `root:123456` 同步替换为强密码

### 2.3 CORS 配置过于宽松

- **位置**：[main.py](file:///d:/智聘云图/backend/app/main.py#L78-L84)
- **现状**：`allow_methods=["*"]`, `allow_headers=["*"]`
- **方案**：
  ```python
  allow_methods=["GET", "POST", "PUT", "DELETE", "PATCH"],
  allow_headers=["Authorization", "Content-Type", "X-Trace-Id"],
  ```
  生产环境 `allow_origins` 仅列前端域名，移除 localhost

### 2.4 接口文档生产环境暴露

- **位置**：[main.py](file:///d:/智聘云图/backend/app/main.py#L71-L73)
- **风险**：`/docs`、`/redoc`、`/openapi.json` 泄露全部 API 结构
- **方案**：
  ```python
  docs_url="/docs" if settings.APP_DEBUG else None,
  redoc_url=None if settings.is_production else "/redoc",
  openapi_url=None if settings.is_production else "/openapi.json",
  ```

### 2.5 缺失速率限制（防暴力登录）

- **现状**：`/auth/login` 无任何频率限制，可被脚本爆破
- **方案**：引入 `slowapi` 中间件
  ```python
  from slowapi import Limiter
  from slowapi.util import get_remote_address

  limiter = Limiter(key_func=get_remote_address)
  # 登录: 5次/分钟/IP
  @router.post("/login")
  @limiter.limit("5/minute")
  async def login(request: Request, ...): ...
  # 匹配接口: 10次/分钟/用户
  @router.get("/match/score")
  @limiter.limit("10/minute")
  def get_match_score(...): ...
  ```
  覆盖范围：登录、注册、匹配、简历上传

### 2.6 其他安全加固

| 项目 | 现状 | 方案 |
|------|------|------|
| 密码复杂度 | 注册无校验 | Pydantic validator：至少 8 位，含字母+数字 |
| 文件上传校验 | 仅校验扩展名 | 增加 magic number 校验（PDF: `%PDF`, DOCX: `PK`） |
| 日志脱敏 | `logger.exception` 记录完整堆栈 | 手机号/邮箱/密码字段脱敏后入库 |
| SQL 注入 | ✅ 全部 ORM 参数化 | 无需修改 |
| 文件路径遍历 | ✅ MD5 哈希存储 | 无需修改 |

## 三、逻辑修正（P1）

### 3.1 ★ 匹配度权重不一致（高优先）

- **问题**：粗排实际权重与前端注释/文档不符
- **后端实际**：[match_service.py L86-93](file:///d:/智聘云图/backend/app/services/match_service.py#L86-L93)
  ```
  技能 35% + 经验 20% + 学历 10% + 城市 10% + 薪资 10% + 项目 15%
  ```
- **前端注释**：[ResumeGraph.vue](file:///d:/智聘云图/frontend/src/views/seeker/ResumeGraph.vue) 与提交记录写的是
  ```
  技能 55% + 经验 20% + 学历 10% + 城市 10% + 薪资 10% + 项目 15%
  ```
- **影响**：用户看到的权重说明与实际计算不符，误导求职者
- **方案**：以后端实际为准（35%），统一修正前端注释、API 文档、能力图谱 tooltip 说明

### 3.2 越权访问风险

- **简历详情**：需校验「求职者仅能访问本人简历」「企业仅能访问已投递简历」
- **消息会话**：需校验「仅会话参与者可查看」
- **图谱接口**：`/graph/resume/{id}` 需校验简历归属
- **方案**：在对应路由补充 `owner_or_admin` 依赖项

### 3.3 简历技能别名映射分散

- **问题**：[ResumeGraph.vue](file:///d:/智聘云图/frontend/src/views/seeker/ResumeGraph.vue) 内硬编码了技能别名映射（office/python/java...），与后端 `match_service._score_skill` 重复
- **方案**：技能归一化逻辑下沉到后端 `skill_service.normalize(name)`，前端只展示后端返回的 matched/missing 结果

### 3.4 投递状态机不完整

- **现状**：状态 0=已投递 1=已查看 2=面试邀请 3=不合适 4=已录用
- **缺失**：无「已拒绝」「已撤回」状态，求职者无法主动撤回投递
- **方案**：增加状态 5=已撤回，求职者可在投递记录页撤回（仅状态=0时允许）

### 3.5 推荐算法冷启动问题

- **问题**：新注册求职者无简历时，`/match/recommend` 返回空列表
- **方案**：无简历时降级为「按求职者意向城市+意向职位类别」召回热门职位

## 四、性能优化（P1）

### 4.1 Redis 缓存层（未启用）

- **现状**：[config.py L32](file:///d:/智聘云图/backend/app/core/config.py#L32) 配置了 `REDIS_URL` 但代码中未使用
- **方案**：封装 `cache_service`，覆盖以下热点：
  | 缓存对象 | TTL | 失效策略 |
  |---------|-----|---------|
  | 职位列表（分页） | 5 分钟 | 职位增删改时清空 `jobs:list:*` |
  | 职位详情 | 10 分钟 | 职位更新时删除 `job:detail:{id}` |
  | 匹配分数 | 2 小时 | 与现有 match_record 缓存策略对齐 |
  | 用户信息 | 30 分钟 | 登录/更新时刷新 |
  | 技能词典 | 1 小时 | 管理员更新时清空 |
- **预期**：列表接口 P99 从 ~200ms 降至 ~20ms

### 4.2 LLM 调用异步化

- **现状**：[match_service.py](file:///d:/智聘云图/backend/app/services/match_service.py) 精排虽用 ThreadPoolExecutor 并发，但接口仍同步等待
- **方案**：
  1. 匹配接口改为 `async def`，LLM 调用用 `asyncio.to_thread` 包装
  2. 长耗时推荐（>3s）改为异步任务：返回 `task_id`，前端轮询 `/match/task/{task_id}`
  3. 引入 Celery（config 已配 broker）处理简历解析、批量推荐

### 4.3 Vite 打包优化

- **位置**：[vite.config.ts](file:///d:/智聘云图/frontend/vite.config.ts)
- **现状**：无 `build.rollupOptions`，echarts/element-plus 全量打包导致首屏 >2MB
- **方案**：
  ```ts
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'vendor-vue': ['vue', 'vue-router', 'pinia'],
          'vendor-ui': ['element-plus', '@element-plus/icons-vue'],
          'vendor-echarts': ['echarts'],
          'vendor-marked': ['marked', 'highlight.js'],
        },
      },
    },
    chunkSizeWarningLimit: 1000,
  },
  ```
- **预期**：首屏体积从 ~2MB 降至 ~400KB，echarts 按需加载

### 4.4 数据库连接池调优

- **现状**：未显式配置 `pool_size`、`max_overflow`、`pool_recycle`
- **方案**：
  ```python
  engine = create_engine(
      settings.DATABASE_URL,
      pool_size=10,
      max_overflow=20,
      pool_recycle=3600,  # MySQL 默认 wait_timeout 8h, 1h 回收避免断连
      pool_pre_ping=True,  # 连接前 ping, 避免使用已断开连接
  )
  ```

### 4.5 前端请求优化

| 问题 | 方案 |
|------|------|
| 无请求取消 | 路由切换时取消 pending 请求（AbortController） |
| 无请求重试 | 网络错误自动重试 1 次（仅 GET） |
| 无全局 loading | request 拦截器维护 pending 计数，>300ms 显示 loading |
| 重复请求 | 相同 GET 请求 200ms 内去重（ debounce） |

## 五、功能扩展（P2）

### 5.1 职位搜索与筛选

- **现状**：[Jobs.vue](file:///d:/智聘云图/frontend/src/views/seeker/Jobs.vue) 仅列表展示，无搜索
- **方案**：
  - 后端：`/jobs` 增加 `keyword`、`city`、`salary_min`、`salary_max`、`education`、`experience` 参数
  - 前端：顶部搜索栏 + 多选筛选侧栏
  - 数据库：`job` 表 `title`、`description` 建全文索引（MySQL FULLTEXT）

### 5.2 简历在线编辑

- **现状**：仅支持文件上传
- **方案**：增加「在线编辑」入口，支持表单式编辑（基本信息/教育/工作/项目/技能），保存后与解析结果合并
- **价值**：降低用户使用门槛，提升简历完整度

### 5.3 面试邀请流程

- **现状**：投递状态有「面试邀请」但无独立流程
- **方案**：
  - 企业端：投递管理页「发送面试邀请」按钮 → 填写时间/地点/形式 → 生成日历事件
  - 求职者端：消息中心收到邀请 → 接受/拒绝 → 状态同步
  - 数据模型：新增 `interview` 表（application_id, time, location, type, status）

### 5.4 消息实时推送

- **现状**：[Message.vue](file:///d:/智聘云图/frontend/src/views/Message.vue) 轮询拉取
- **方案**：引入 WebSocket（FastAPI 原生支持）
  ```python
  @app.websocket("/ws/message/{user_id}")
  async def ws_message(websocket: WebSocket, user_id: int): ...
  ```
  前端建立长连接，新消息实时推送，减少无效轮询

### 5.5 数据导出

- **现状**：admin 仪表盘无导出
- **方案**：用户列表/简历列表/职位列表增加「导出 Excel」按钮，后端用 `openpyxl` 生成

### 5.6 简历预览

- **现状**：简历列表只能下载原文件
- **方案**：集成 `pdf.js` / `docx-preview` 在线预览，避免下载等待

### 5.7 职位订阅

- **方案**：求职者订阅意向（城市+职位类别），新职位发布时推送消息

### 5.8 企业资质认证

- **现状**：企业注册即可发职位
- **方案**：企业用户需上传营业执照，管理员审核通过后才能发布职位

### 5.9 数据统计报表

- **方案**：admin 仪表盘增加「招聘漏斗」「职位热度榜」「匹配成功率趋势」图表

## 六、前端体验提升（P3）

### 6.1 骨架屏

- **问题**：列表加载时空白，用户感知卡顿
- **方案**：为 Jobs、Applications、Candidates 等列表页增加 `el-skeleton` 骨架屏

### 6.2 空状态优化

- **问题**：无数据时显示空白或「暂无数据」
- **方案**：统一空状态组件，含插图 + 引导文案 + 操作按钮（如「去上传简历」）

### 6.3 表单校验完善

- **问题**：[Register.vue](file:///d:/智聘云图/frontend/src/views/auth/Register.vue) 校验规则不完整
- **方案**：密码强度实时提示、手机号格式校验、用户名长度/敏感词过滤

### 6.4 移动端适配

- **现状**：未做响应式
- **方案**：关键页面（职位列表、投递记录、消息）增加 `@media` 断点，支持 375px 宽度

### 6.5 全局错误边界

- **方案**：Vue `app.config.errorHandler` 捕获未处理异常，展示友好错误页

### 6.6 性能监控

- **方案**：接入 Web Vitals，上报 LCP/FID/CLS，后端 `/api/v1/metrics/web-vitals` 接收

## 八、验收标准

| 维度 | 指标 | 目标 |
|------|------|------|
| 安全 | JWT 密钥 | 启动校验通过，非默认值 |

## 九、风险与回滚

- 每阶段独立提交，保留回滚能力
- Redis 缓存采用「旁路缓存」模式，缓存故障自动降级到数据库
- 速率限制初期阈值宽松，观察一周后收紧
- WebSocket 与轮询并行运行 1 周，确认稳定后下线轮询

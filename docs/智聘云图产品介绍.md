# 智聘云图 - 产品介绍文档

> 基于文档智能解析的人岗匹配平台 | v1.0.0

---

## 一、产品概述

**智聘云图**是一款面向企业招聘和人才求职场景的智能 B/S 架构平台，以"AI 驱动的文档智能解析与精准人岗匹配"为核心设计理念，致力于解决传统招聘流程中 JD（职位描述）撰写效率低、简历筛选耗时、人岗匹配不精准等痛点。

平台深度集成火山引擎 **豆包大模型（doubao-seed-2-1-pro）**，通过 Prompt Engineering 技术构建了专业的简历解析、JD 结构化、匹配重排三大 AI 工作流，能够在数分钟内完成从文档上传到智能匹配的全链路自动化处理。同时，系统内置知识图谱可视化（Neo4j）、向量检索（Embedding）和缓存加速机制，为招聘双方提供高效、智能、可视化的决策支持。

系统采用经典的三端分离架构，分别为**求职者端**、**企业端**和**管理后台**，覆盖了招聘全生命周期的核心场景：简历上传与 AI 解析、职位发布与 JD 智能填充、人岗匹配与推荐排序、投递管理与状态流转、站内消息与沟通协作，以及平台级的数据监控与日志审计。

## 二、核心功能

### 2.1 文档智能解析

这是平台最核心的 AI 能力之一，基于豆包大模型的多轮 Prompt 工程实现，支持多种输入格式的智能结构化和字段级填充。

#### 2.1.1 简历智能解析

求职者上传 PDF / DOC / DOCX 格式的简历文件后，系统调用 `doubao-seed-2-1-pro` 模型进行深度语义理解，自动提取以下结构化字段：

- **基本信息**: 姓名、性别、年龄、手机号、邮箱、当前居住城市、意向城市
- **教育背景**: 最高学历、毕业院校、专业
- **工作经历**: 公司名称、职位、任职时长、工作内容描述（按时间倒序）
- **项目经历**: 项目名称、角色、项目描述
- **技能标签**: 技能名称、熟练程度（精通 / 熟练 / 掌握 / 了解），自动归一化处理（如 `js` → `JavaScript`）
- **自我评价**: 从简历中提取或归纳

AI 解析完成后，系统自动将结构化数据填充到数据库中，并为求职者生成可视化能力图谱、技能雷达图等个人画像展示。

#### 2.1.2 JD 智能解析

企业在发布职位时，可通过两种方式触发 AI 解析：

1. **文件上传**: 上传 PDF / DOC / DOCX 格式的 JD 文件，系统自动提取文本并调用 AI 解析
2. **文本粘贴**: 将 JD 文本直接粘贴到输入框，点击"AI 解析文本"按钮触发解析

AI 解析引擎（`doubao-seed-2-1-pro` 推理模型，约 1-3 分钟）支持**任意格式**的 JD 输入，无论是规范的结构化文档还是口语化的非规范描述，均能通过语义理解提取以下字段：

- 职位名称（根据职责描述自动推断，如"前端开发工程师"）
- 公司名称、所属部门
- 工作城市、工作性质（全职 / 兼职 / 实习，默认推断为全职）
- 薪资范围（自动归一化为 K 单位，如 `20000 元` → `20K`）
- 经验要求、学历要求
- 招聘人数
- 职位描述（AI 归纳为 2-3 句通顺的概况文本）
- 技能要求（最多提取 8 项核心技能，含技能名称、熟练程度、必须/优先标签）

解析完成后，系统将结果以摘要面板形式展示（字段级对比），并自动将结构化数据填入表单，用户可在此基础上编辑修改后发布。

**技术优化**: 针对长文本 JD（1500+ 字符），通过限制 `max_tokens=1024` 和优化 Prompt（限制 description 不超过 200 字、requirements 最多 8 项），将输出量从 2900+ 字符缩减至 1000 字符左右，减少约 64% 的生成量，同时保持解析质量。

#### 2.1.3 解析进度与反馈

系统提供完整的解析进度反馈链：
- 文件上传区：上传完成显示绿色边框 + 文件名 + 成功图标（弹跳动画）
- 状态提示条：实时显示"正在上传并调用 AI 解析 JD，请耐心等待（doubao-seed 推理模型，预计 1-3 分钟）"
- 解析摘要面板：展示 AI 识别了哪些字段、每个字段的具体值，未识别字段标记为"未识别"
- 技能要求预览：以标签形式展示解析出的技能名称、熟练程度和优先级

### 2.2 人岗智能匹配

匹配引擎是平台的核心竞争力，采用"IE 规则粗筛 + LLM 语义精排 + 缓存加速"的三层架构。

#### 2.2.1 匹配流程

1. **IE 规则粗筛**: 基于技能关键词进行快速交集计算，计算 `matched / total_required` 的规则匹配分
2. **LLM 语义精排**: 调用豆包大模型对候选对进行语义级评估，综合考虑技能匹配度、经验年限、学历、薪资期望等多维度因素，输出 0-100 的综合匹配分和自然语言匹配理由
3. **缓存加速**: 查询 `match_record` 表，对 2 小时内的近期匹配结果直接复用，将重复查询耗时从 3 秒降至 0.09 秒

#### 2.2.2 批量重排优化

采用 `build_batch_rerank_messages` 将 4 个候选合并为 1 次 LLM 调用，减少 API 调用次数，将匹配耗时从 28 秒降至 3 秒。

#### 2.2.3 双端匹配

- **求职者端**: 职位推荐 — 根据简历内容，从全平台职位库中推荐匹配度最高的职位，展示匹配分和匹配理由
- **企业端**: 候选人推荐 — 根据职位要求，从全平台简历库中推荐匹配度最高的候选人，展示匹配分、已匹配技能、缺失技能

#### 2.2.4 匹配分析面板

在投递管理页面，每条投递记录均展示匹配度百分比和缺失技能数量。点击"查看简历"可展开详细抽屉，包含：
- 环形匹配度仪表盘（颜色随分数变化：绿 / 蓝 / 黄 / 红）
- 已匹配技能列表 + 缺失技能警告（红色标签）
- 完整的简历信息、工作经历 Timeline、项目经历 Timeline、技能标签云

### 2.4 知识图谱可视化

系统集成了 Neo4j 图数据库，构建了以**技能**为核心的关联知识图谱：

- **简历能力图谱**: 以求职者为中心，展示其掌握的技能及关联关系
- **职位能力图谱**: 以职位为中心，展示其要求的技能体系
- **技能关联图谱**: 展示技能之间的关联关系（如 Python → 数据分析 → 机器学习）

图谱功能依赖于 Neo4j 数据库，在未安装 Neo4j 驱动时自动降级为静态展示模式，不影响核心业务功能。

### 2.5 投递管理与状态流转

投递管理系统支持完整的招聘状态流转：

```
已投递(0) → 已查看(1) → 面试邀请(2) → 已录用(4)
                       ↘ 不合适(3)
```

关键功能：
- 企业可按职位、状态、候选人姓名进行多维度筛选
- 支持按**匹配度从高到低**、**投递时间最新**、**投递时间最早**三种排序方式
- 支持**批量更新状态**（勾选多条记录后统一修改为同一状态）
- 状态变更时自动向求职者发送站内消息通知
- 信息脱敏处理：企业对求职者电话号码和邮箱进行掩码显示（如 `138****1234`）

### 3.5 安全与权限

- **JWT 认证**: 双令牌机制（Access Token 120 分钟 + Refresh Token 7 天），支持令牌刷新
- **角色体系**: 三种角色（ROLE_SEEKER / ROLE_EMPLOYER / ROLE_ADMIN），路由级 + API 级双重校验
- **IDOR 防护**: 企业仅可操作本企业职位和投递记录，求职者仅可操作本人简历和投递
- **密码安全**: bcrypt 哈希存储，不可逆加密
- **信息脱敏**: 企业端查看求职者联系方式时自动掩码处理
- **CORS 配置**: 白名单机制，仅允许信任的前端域名访问
- **操作审计**: 管理后台记录所有操作日志，含操作人、时间、IP 地址

## 四、业务流程详解

### 4.1 求职者投递流程

```
上传简历 → AI 解析 → 浏览职位广场 / 查看推荐 → 投递简历 → 等待企业反馈 → 查看状态变更 → 消息沟通
```

### 4.2 企业招聘流程

```
上传 JD / 粘贴文本 → AI 解析并填充表单 → 编辑确认 → 发布职位 → 查看候选人推荐 → 筛选投递记录 → 查看简历 → 更新状态 → 联系候选人
```

### 4.3 匹配引擎流程

```
简历上传/职位发布 → 技能标签提取 → Embedding 向量化 → IE 规则粗筛 → LLM 语义精排 → 缓存结果 → 展示匹配分析
```

## 五、性能优化策略

系统在开发过程中沉淀了多项性能优化实践：

| 优化项 | 策略 | 效果 |
|--------|------|------|
| **批量重排** | 4 个候选合并为 1 次 LLM 调用 | 28s → 3s |
| **重排缓存** | 查询 match_record，2h 内复用 | 3s → 0.09s |
| **Embedding 降级** | 首个 404 后跳过重试，`_embedding_disabled` 标记 | 避免无效 API 消耗 |
| **selectinload 预加载** | 关联数据预加载，消除 N+1 查询 | 显著减少 DB 查询次数 |
| **max_tokens 调优** | 批量重排 1024，单次 256 | 平衡质量和速度 |
| **echo=False** | 关闭 SQLAlchemy SQL 日志 | 减少 I/O 开销 |
| **Vite 代理优化** | 使用 `127.0.0.1` 而非 `localhost` | 避免 IPv6 解析延迟（~2s/请求） |
| **JD 解析输出优化** | 限制 description 200 字 + requirements 8 项 | 输出量减少 64%，耗时减少 16% |

## 七、项目亮点总结

1. **AI 原生**: 以豆包大模型为核心，构建了覆盖简历解析、JD 结构化、匹配重排的完整 AI 工作流，支持任意格式的输入文本
2. **三端分流**: 求职者、企业、管理员三端独立工作台，路由级 + API 级双重角色鉴权
3. **智能匹配**: 三层匹配架构（规则粗筛 + LLM 精排 + 缓存加速），匹配分析可视化（匹配度、已匹配技能、缺失技能）
4. **知识图谱**: Neo4j 图数据库构建技能关联网络，可视化展示个人能力画像和职位技能体系
5. **状态流转**: 完整的投递状态生命周期管理，自动通知 + 批量操作

## 第一章 产品概述

### 1.1 产品定位

智聘云图是一款基于文档智能解析的人岗匹配平台, 采用 B/S 架构, 面向求职者、企业招聘方、平台管理员三类用户群体, 通过大语言模型 (LLM) 自动解析简历文档, 构建能力知识图谱, 并运用六维度匹配引擎实现精准的人岗双向推荐。

### 1.2 核心价值

- **智能解析**: 上传简历文档 (PDF/DOC/DOCX), 大模型自动提取结构化信息, 无需手动填写
- **能力图谱**: 将简历技能可视化为知识图谱, 直观展示能力分布与岗位匹配缺口
- **精准推荐**: 六维度加权匹配算法 (技能/经验/学历/城市/薪资/项目), 结合大模型精排, 推荐结果有理有据
- **三端协同**: 求职者、企业、管理员三端独立工作台, 数据互通, 角色隔离

### 1.3 适用场景

- 高校毕业生求职就业
- 企业招聘人才筛选
- 招聘平台运营管理
- 毕业设计答辩演示

## 第二章 技术架构

### 2.1 整体架构

┌─────────────────────────────────────────┐
│              前端 (Vue3 + Vite)           │
│  Element Plus + ECharts + Pinia          │
├─────────────────────────────────────────┤
│              Vite Dev Proxy              │
├─────────────────────────────────────────┤
│           后端 (FastAPI + Uvicorn)        │
│  SQLAlchemy ORM + Pydantic + slowapi     │
├──────────────┬──────────────────────────┤
│  GreatSQL DB │  灵犀大模型 ARK API       │
│  (数据持久化)  │  (简历解析/匹配/分析)      │

## 第三章 角色体系与权限

### 3.1 三角色体系

系统采用基于角色的访问控制 (RBAC), 共三个角色:

| 角色 | 标识 | 工作台路径 | 核心职责 |
|------|------|-----------|----------|
| 求职者 | ROLE_SEEKER | /seeker | 上传简历、浏览职位、投递申请 |
| 企业 | ROLE_EMPLOYER | /employer | 发布职位、筛选候选人、管理投递 |
| 管理员 | ROLE_ADMIN | /admin | 平台运营、数据监控、用户管理 |

### 3.2 权限隔离机制

- **路由守卫**: 前端路由配置 `role` 元信息, 路由守卫校验用户角色与路径前缀匹配
- **后端鉴权**: 每个 API 接口通过 `require_role("ROLE_XXX")` 依赖注入校验权限
- **数据隔离**: 求职者只能操作自己的简历, 企业只能管理自己的职位
- **JWT 认证**: 所有请求携带 Bearer Token, 后端解析验证

### 3.3 注册与登录

- **注册流程**: 选择角色 (求职者/企业) → 填写用户名/密码/邮箱 → 密码复杂度校验 (8位+字母+数字) → 注册成功
- **登录流程**: 用户名 + 密码 → JWT Token 签发 (Access Token 2h + Refresh Token 7d) → 前端存储 → 路由跳转
- **安全增强**: 登录接口限速 5次/分钟, 密码 bcrypt 加密存储, SECRET_KEY 生产环境强制随机

## 第四章 求职者端功能

### 4.1 个人仪表盘

求职者登录后的首页, 展示:

- **简历概览**: 已上传简历数量、解析状态
- **投递统计**: 总投递数、各状态分布 (待处理/已查看/面试邀请/不合适)
- **推荐职位**: 系统根据简历智能推荐的热门职位
- **快速入口**: 上传简历、浏览职位、查看投递记录

### 4.2 简历管理

#### 4.2.1 上传简历

- **支持格式**: .doc / .docx / .pdf, 最大 10MB
- **操作流程**: 选择文件 → 点击"开始上传并解析" → AI 自动解析 → 展示结构化结果
- **解析步骤**: 文件上传 → 文本提取 → AI 结构化 → AI 智能分析 → 完成
- **安全校验**: 文件 magic number 校验, 防止伪造文件类型
- **超时设置**: 10 分钟, 足够大模型完成解析

#### 4.2.2 AI 智能分析 (上传阶段自动完成)

简历解析成功后, 系统自动调用大模型进行智能分析:

- **完整度评分**: 0-100 分, 评估简历完善程度
- **改进建议**: 按优先级 (重要/建议/可选) 分类展示
- **分析维度**: 基本信息、教育背景、技能清单、工作经历、项目经历、自我评价、期望薪资、求职意向
- **一键采纳**: 点击"采纳并编辑"自动跳转到编辑页, 建议内容预填到表单

#### 4.2.3 在线编辑简历

- **编辑入口**: 简历列表页"编辑"按钮, 或上传页"去编辑简历"按钮
- **可编辑字段**: 基本信息 (姓名/性别/年龄/手机/邮箱/城市)、教育背景 (学历/学校/专业)、期望薪资、自我评价、技能清单
- **技能管理**: 动态增删技能, 每个技能可设置掌握程度 (精通/熟练/掌握/了解)
- **表单校验**: 手机号格式、邮箱格式、必填项校验
- **保存机制**: 仅更新非空字段, 技能全量替换

#### 4.2.4 简历列表

- 展示所有已上传简历, 含姓名、学历、学校、专业、解析状态
- **操作菜单**: 查看详情、编辑、能力图谱、推荐职位、删除
- **删除确认**: 二次确认弹窗, 防止误删

### 4.3 职位广场

- **职位卡片**: 展示职位标题、公司、薪资、城市、学历要求
- **搜索筛选**: 关键词搜索 + 城市/学历/薪资区间多条件筛选
- **分页加载**: 每页 10 条, 支持翻页
- **快速操作**: 查看详情、收藏职位、一键投递

### 4.4 职位详情

#### 4.4.1 基本信息

- 展示职位完整信息: 标题、公司、薪资范围、工作城市、学历要求、经验要求
- **岗位描述**: 详细岗位职责与任职要求
- **技能要求清单**: 分"必须"和"优先"两类展示

#### 4.4.2 岗位能力要求图谱

- **可视化展示**: 力导向图谱, 中心节点显示岗位名称
- **节点颜色**: 红色 = 必须技能, 黄色 = 优先技能

#### 4.4.3 投递操作

- **智能推荐**: 基于简历技能, 大模型精排推荐匹配职位

- **匹配度展示**: 底部环形进度条 + 已匹配/缺失技能标签

### 4.7 投递记录

- **时间线**: 展示投递时间轴

### 4.8 我的收藏

- 快速跳转职位详情或投递

### 4.9 消息中心

### 4.10 个人设置

## 第七章 AI 智能引擎

### 7.1 大模型接入

系统接入字节跳动豆包大模型 (ARK API), 核心模型:

- **对话模型**: doubao-seed-2-1-pro-260628 (简历解析、匹配、分析)
- **API 地址**: https://ark.cn-beijing.volces.com/api/v3

### 7.2 简历智能解析

- **输入**: 简历文档文本 (PDF/DOCX 提取)
- **输出**: 结构化 JSON (基本信息 + 教育背景 + 技能清单 + 工作经历 + 项目经历)
- **Prompt 工程**: 精心设计的系统提示词, 确保输出格式稳定
- **容错机制**: 解析失败自动重试, 记录失败原因

### 7.3 AI 简历智能分析

- **触发时机**: 简历解析成功后自动调用
- **分析维度**: 8 个维度 (基本信息/教育/技能/工作/项目/自评/薪资/意向)
- **输出**: 完整度评分 + 改进建议列表 (优先级 + 分类 + 建议 + 采纳动作)
- **一键采纳**: 技能类建议自动添加到技能清单, 文本/数值类建议预填表单

### 7.4 AI 智能匹配

- **粗排规则**: 六维度加权计算快速筛选
- **精排模型**: 大模型综合评估生成匹配理由
- **批量优化**: 4 个候选人合并为 1 次 LLM 调用, 28s → 3s
- **缓存机制**: 2 小时窗口内重复查询复用结果, 3s → 0.09s

## 第八章 六维度匹配引擎

### 8.1 维度权重

| 维度 | 权重 | 计算依据 |
|------|------|----------|
| 技能匹配 | 40% | 岗位要求技能 vs 简历技能 (含别名归一化) |
| 经验匹配 | 20% | 岗位要求年限 vs 简历工作年限 |
| 学历匹配 | 15% | 岗位要求学历 vs 简历学历 |
| 城市匹配 | 10% | 岗位城市 vs 简历意向城市 |
| 薪资匹配 | 10% | 岗位薪资范围 vs 简历期望薪资 |
| 项目匹配 | 5% | 简历项目经历相关度 |

### 8.2 技能别名归一化

系统内置技能别名映射表, 解决技能名称不一致问题:

- Java ↔ java ↔ java语言 ↔ JDK
- Python ↔ python ↔ python3 ↔ py
- MySQL ↔ mysql ↔ SQL ↔ 数据库
- Vue ↔ vue ↔ vue.js ↔ vuejs
- Docker ↔ docker ↔ 容器 ↔ 容器化
- Kubernetes ↔ kubernetes ↔ k8s

### 8.3 匹配度统一数据源

全系统匹配度数据统一由后端 `/match/score` 接口提供, 确保各页面展示一致:

- 简历推荐页
- 职位推荐页
- 能力图谱页
- 候选人推荐页

## 第九章 系统扩展功能

### 9.1 面试邀请流程

- **模型**: Interview (面试时间、地点、形式、备注)
- **流程**: 企业发送邀请 → 求职者接收通知 → 求职者接受/拒绝
- **状态管理**: 待回复 / 已接受 / 已拒绝 / 已取消

### 9.2 企业资质认证

- **模型**: EnterpriseLicense (营业执照、认证状态)
- **流程**: 企业上传营业执照 → 管理员审核 → 认证通过/拒绝
- **信任标识**: 认证通过的企业展示"已认证"标识

### 9.3 职位订阅

- **模型**: JobSubscription (订阅条件、通知频率)
- **功能**: 求职者订阅意向职位条件, 新职位发布时推送通知
- **管理**: 订阅列表查看、取消订阅

### 9.4 WebSocket 消息推送

- **实时通信**: WebSocket 长连接, 消息即时送达
- **应用场景**: 面试邀请通知、投递状态变更、系统公告
- **降级机制**: WebSocket 不可用时降级为轮询

### 9.5 性能监控 (Web Vitals)

- **采集指标**: LCP (最大内容绘制)、FID (首次输入延迟)、CLS (累积布局偏移)
- **上报机制**: 前端自动采集, POST /metrics 接口接收
- **数据用途**: 监控页面加载性能, 优化用户体验

## 第十章 安全与性能

### 10.1 安全加固

#### 10.1.1 认证安全

- **JWT 密钥**: 生产环境强制随机密钥 (拒绝默认值启动)
- **Token 有效期**: Access Token 2h, Refresh Token 7d
- **密码存储**: bcrypt 加密, 不存储明文
- **密码复杂度**: 最少 8 位, 必须包含字母和数字

#### 10.1.2 接口安全

- **速率限制**: 登录接口 5次/分钟, 防止暴力破解
- **CORS 收紧**: 仅允许配置的来源, 限制方法和头部
- **文件上传校验**: magic number 校验文件真实类型
- **生产环境**: 关闭 /docs、/redoc、/openapi.json 接口

#### 10.1.3 数据安全

- **日志脱敏**: 手机号、邮箱等敏感信息脱敏处理
- **SQL 注入防护**: SQLAlchemy ORM 参数化查询
- **XSS 防护**: 前端输入转义, v-html 谨慎使用

### 10.2 性能优化

#### 10.2.1 后端优化

- **Redis 缓存**: 热点数据缓存, 降级保护 (Redis 不可用时静默降级)
- **N+1 查询消除**: selectinload 预加载关联数据
- **批量精排**: 4 候选人合并 1 次 LLM 调用, 减少 API 调用
- **匹配缓存**: 2 小时窗口复用历史匹配结果
- **SQL 日志关闭**: 生产环境 echo=False

#### 10.2.2 前端优化

- **路由懒加载**: 所有页面组件动态 import, 按需加载
- **Vite 打包优化**: manualChunks 分包, vendor 独立打包
- **请求去重**: 相同 GET 请求复用结果
- **GET 重试**: 网络错误自动重试 1 次
- **骨架屏**: 列表页加载时展示骨架屏, 提升感知速度
- **空状态处理**: 无数据时展示友好空状态

#### 10.2.3 超时配置

- **Vite Proxy**: 600000ms (10 分钟)
- **Axios 全局**: 600000ms
- **简历上传**: 600000ms
- **AI 匹配**: 600000ms
- **AI 分析**: 600000ms

### 11.1 环境要求

- **操作系统**: Windows / macOS / Linux
- **Python**: 3.11+
- **Node.js**: 18+
- **数据库**: GreatSQL 8.0 (MySQL 兼容)
- **Redis**: 可选 (不可用时自动降级)

### 11.2 后端启动

```bash
# 1. 进入后端目录
cd backend

# 2. 创建虚拟环境
python -m venv venv
source venv/bin/activate  # Linux/Mac
venv\Scripts\activate     # Windows

# 3. 安装依赖
pip install -r requirements.txt

# 4. 配置环境变量
# 编辑 .env.dev, 填入 ARK_API_KEY 等

# 5. 启动服务
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```bash
# 1. 进入前端目录
cd frontend

# 2. 安装依赖
npm install

# 3. 启动开发服务器
npx vite --port 5174

# 4. 构建生产包
npm run build
```

## 第十二章 常见问题

### 12.1 简历解析失败

**现象**: 上传简历后解析状态为"失败"

**排查**:
1. 检查 ARK_API_KEY 是否正确配置
2. 查看后端日志中的 parse_error 字段
3. 确认文件格式为 PDF/DOC/DOCX 且未损坏
4. 文件大小不超过 10MB

### 12.2 图谱技能连线缺失

**现象**: 已匹配技能未在图谱连线

**原因**: 技能名称存在别名 (如"Java" vs "java语言")

**解决**: 系统已内置技能别名归一化映射, 若仍有问题可检查技能名称是否在映射表中

### 12.3 匹配度显示不一致

**现象**: 不同页面匹配度不同

**解决**: 系统已统一匹配度数据源为 `/match/score` 接口, 若仍不一致请清除浏览器缓存

### 12.4 上传超时

**现象**: 上传简历提示超时

**解决**: 系统已将超时设置为 10 分钟, 若仍超时请检查网络或大模型服务状态

### 12.5 Neo4j 未安装

**现象**: 后端日志提示 "neo4j 驱动未安装"

**说明**: 知识图谱功能已自动降级为 SQLite 实现, 不影响正常使用

### 12.6 Redis 不可用

**现象**: 后端日志提示 "Redis 不可用"

**说明**: 缓存功能已自动降级, 系统正常运行但性能略有下降

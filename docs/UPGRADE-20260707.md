## 二、BUG-34：薪资输入被截断

### 现象
用户在发布职位时,薪资下限输入 3000、上限输入 5000,但保存后都显示 999。

### 根因
[JobCreate.vue](file:///d:/智聘云图/frontend/src/views/employer/JobCreate.vue) 中薪资输入组件 `el-input-number` 设置了 `:max="999"`,用户输入 3000 超出上限被截断为 999。
当前薪资单位为 K(千元),3000 元 = 3K,用户误以为输入的是元。

### 修复方案
1. **调整 max 上限**: `:max="999"` → `:max="999"` 保持不变(K 单位下 999K = 99.9 万已足够),但增加 `:step="1"` 和更清晰的 placeholder。
2. **明确单位提示**: label 从"薪资下限 (K)"改为"薪资下限 (K, 如 3 表示 3 千)"，placeholder 增加"单位:K(千元)"。
3. **前端校验**: 提交前提示"薪资单位为 K, 如 3000 元请输入 3"。

### 涉及文件
- `frontend/src/views/employer/JobCreate.vue` — 薪资输入组件 label + placeholder + 前端提示

## 三、BUG-35：学历要求选项调整

### 现象
当前学历选项为"不限/大专/本科/硕士/博士",不符合实际招聘表述(应为"专科及以上")。

### 修复方案

## 六、ENH-38：数据库迁移 SQLite → GreatSQL/MySQL

### 现状
- 当前数据库: SQLite (`backend/zhipin.db`, 372KB)
- 本机已有: MySQL 8.0.39 (root/123456, 服务名 MySQL80, 运行中)
- GreatSQL 兼容 MySQL 8.0 协议,SQL 语法/连接方式完全一致

### 迁移方案

#### 1. 环境准备
- 安装 Python MySQL 驱动: `pip install pymysql`
- 在 MySQL 中创建数据库:
  ```sql
  CREATE DATABASE zhipin CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  ```

#### 2. 修改配置
- `.env.dev` 中 `DATABASE_URL` 改为:
  ```
  DATABASE_URL=mysql+pymysql://root:123456@127.0.0.1:3306/zhipin?charset=utf8mb4
  ```

#### 3. 模型适配
- `backend/app/db/base.py` 中 `BigIntPK` 已用 `with_variant(Integer, "sqlite")` 处理 SQLite,MySQL 下自动使用 `BigInteger`(需添加 `autoincrement=True`)
- MySQL 下 `BigInteger` 自增需声明 `autoincrement=True`,否则不会自增
- `func.now()` 在 MySQL 下映射为 `CURRENT_TIMESTAMP`,兼容
- `LargeBinary` 在 MySQL 下映射为 `BLOB`,兼容(但 embedding 字段可能较长,需用 `MEDIUMBLOB`)

#### 4. 数据迁移脚本
编写 `backend/scripts/migrate_sqlite_to_mysql.py`:
1. 连接 SQLite 源数据库(读取所有表数据)
2. 连接 MySQL 目标数据库
3. `Base.metadata.create_all()` 在 MySQL 中建表
4. 逐表读取 SQLite 数据,通过 ORM 批量写入 MySQL
5. 验证数据完整性(行数对比)
6. 保留 SQLite 原文件作为备份

#### 5. 数据完整性保障
- 迁移前备份 `zhipin.db` → `zhipin.db.bak`
- 迁移后验证各表行数一致
- 如失败可回滚到 SQLite (恢复 .env.dev)

### 涉及文件
- `backend/.env.dev` — DATABASE_URL
- `backend/app/db/base.py` — BigIntPK autoincrement
- `backend/scripts/migrate_sqlite_to_mysql.py` — 新增迁移脚本
- `backend/requirements.txt` — 添加 pymysql

## 十、BUG-39：发布职位超时

### 现象
发布职位时如果附带 JD 文本(parse_text), 后端会调用 AI 解析, 耗时可能超过 30 秒, 前端默认 30s 超时导致请求失败。

### 根因
`frontend/src/api/request.ts` 全局默认 `timeout: 30000`(30 秒), `jobApi.create` 未单独设置超时。

### 修复方案
`jobApi.create` 增加 `timeout: 120000`(120 秒), 与 `matchApi.recommendJobs` 一致。

### 涉及文件
- `frontend/src/api/job.ts` — create 方法增加 timeout

## 十八、ENH-44 GreatSQL 迁移 - 完成记录 (2026-07-07 终)

### 迁移步骤
1. **数据导出**: `mysqldump` 导出 zhipin 库 → `backend/zhipin_dump.sql` (209KB, 含 48 简历/56 职位/36 用户)
2. **镜像拉取**: `docker pull greatsql/greatsql:8.0.32-25`
3. **停 MySQL80**: `Stop-Service MySQL80` 释放 3306 端口
4. **启动 GreatSQL 容器**:
   ```
   docker run --name greatsql -p 3306:3306 \
     -e MYSQL_ROOT_PASSWORD=123456 \
     -e MYSQL_DATABASE=zhipin \
     -v greatsql_data:/var/lib/mysql \
     -d greatsql/greatsql:8.0.32-25 \
     --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
   ```
5. **数据导入**: `mysql -h127.0.0.1 -uroot -p123456 zhipin < zhipin_dump.sql`
6. **配置不变**: `.env.dev` DATABASE_URL 端口/密码一致, pymysql 驱动兼容 GreatSQL
7. **验证**: 行数对比 + 后端启动测试

### 涉及文件
- 无代码改动, 纯基础设施切换
- 新增数据卷 `greatsql_data` 持久化
- MySQL80 服务停止后保留(可手动启动作为回滚)

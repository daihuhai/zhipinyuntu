# 智聘云图 - 匹配度统一优化方案

> 文档版本: v3.0  
> 创建日期: 2026-07-12  
> 涉及模块: 能力关系图谱、投递管理、智能匹配引擎、求职者首页  
> 核心目标: **全系统统一匹配度，主体是"简历"而非"用户"，一个分数、一套逻辑、一处计算**

---

## 一、问题背景

### 1.1 用户反馈

> "我是按照简历内容制作的 JD，但是匹配度却只有 43%"  
> "能力概览显示匹配率 60%，岗位匹配度却是 43%，到底哪个准？"

### 1.2 问题根因

当前系统存在**三套独立的匹配度计算逻辑**，结果各不相同：

```
┌─────────────────────────────────────────────────────────────┐
│  能力图谱 - 能力概览 "匹配率"    60%  (分母=求职者技能数)    │
│  能力图谱 - 岗位匹配度          43%  (分母=岗位要求技能数)    │
│  投递管理 - 匹配度              43%  (仅技能字符串匹配)       │
│  后端匹配引擎 (未被调用)        85%+ (六维度加权综合评分)     │
└─────────────────────────────────────────────────────────────┘
```

**三个核心问题**：

1. **匹配度不统一** — 同一份简历对同一个岗位，三个地方显示三个不同的分数
2. **维度缺失** — 前端只算技能匹配（35% 权重），经验/学历/城市/薪资/项目（65%）完全未计入
3. **引擎闲置** — 后端已实现完善的六维度匹配引擎，但前端完全没用上

### 1.3 匹配度主体澄清

**匹配度的主体是"简历"，不是"用户"**：

用户可能上传多份简历（如一份 Java 简历、一份 Python 简历），对同一个岗位的匹配度完全不同。因此：

- 匹配度 = **特定简历** 与 **特定岗位** 的匹配度
- 切换简历时，匹配度应重新计算
- 投递记录中，每条投递绑定的是简历ID（不是用户ID），匹配度对应那份简历

## 二、优化方案

### 2.1 核心原则

**一个匹配度，全系统统一，主体是简历**：

- 所有匹配度**来自同一个数据源** — 后端 `match_service` 的六维度加权评分
- 匹配度始终绑定 resume_id + job_id，而非 user_id + job_id
- 用户切换简历时，匹配度实时重新计算
- 消除前端自行计算匹配度、消除 application API 中的简单字符串匹配

### 2.2 统一匹配度定义

```
匹配度 = f(简历, 岗位) → 0~100 分

  匹配度 = 技能(35%) + 经验(20%) + 学历(10%) + 城市(10%) + 薪资(10%) + 项目(15%)

  技能匹配: 别名归一化 + 等级加权 + 必须/优先权重
  经验匹配: 解析 "3-5年"/"5年以上"/"应届"
  学历匹配: 博士>硕士>本科>大专 层级比较
  城市匹配: 精确 + 意向城市包含检查
  薪资匹配: 区间重叠计算
  项目匹配: 项目数量评分
```

**关键**：匹配度计算入参是 `resume_id + job_id`，与 user_id 无关。同一用户的简历A和简历B对同一岗位的匹配度不同。

### 2.3 改动范围

| 序号 | 文件 | 改动内容 | 说明 |
|------|------|----------|------|
| 1 | `backend/app/api/v1/match.py` | 新增 `GET /match/score` 接口 | 入参 resume_id + job_id，返回六维度匹配分 |
| 2 | `backend/app/api/v1/application.py` | 投递列表匹配度改用 match_service | 替换原有的字符串匹配 |
| 3 | `frontend/src/api/match.ts` | 新增 `matchApi.getScore(resumeId, jobId)` | 前端封装 |
| 4 | `frontend/src/views/seeker/ResumeGraph.vue` | 调用 match API + 雷达图升级 | 删除前端匹配计算 |
| 5 | `frontend/src/views/seeker/ResumeGraph.vue` | 能力概览删除重复"匹配率" | 只保留一个匹配度 |
| 6 | `frontend/src/views/employer/Applications.vue` | 使用后端返回的匹配分 | 无需前端计算 |

### 2.4 新增后端接口

```python
@router.get("/score", summary="获取简历与岗位的匹配分")
def get_match_score(
    resume_id: int = Query(..., description="简历ID"),
    job_id: int = Query(..., description="职位ID"),
    current_user: SysUser = Depends(get_current_user),
    db: Session = Depends(get_db),
):
    """获取简历与岗位的六维度匹配分 (统一匹配度数据源)

    匹配度主体是简历(resume), 不是用户(user)。
    同一用户的多份简历对同一岗位的匹配度不同。
    """
    resume = db.get(Resume, resume_id)
    job = db.get(Job, job_id)
    if not resume or not job:
        return fail(BizError.RESOURCE_NOT_FOUND, "简历或职位不存在")

    # 预加载关联关系 (避免懒加载失败)
    db.refresh(resume, attribute_names=["skills", "projects"])
    db.refresh(job, attribute_names=["requirements"])

    # 调用匹配引擎粗排 (六维度评分, 纯计算无LLM调用)
    scores = match_service.coarse_rank(resume, job)

    return success(data={
        "total_score": scores["total"],
        "skill_score": scores["skill"],
        "experience_score": scores["experience"],
        "education_score": scores["education"],
        "city_score": scores["city"],
        "salary_score": scores["salary"],
        "project_score": scores["project"],
    })
```

**特点**：
- 入参是 resume_id + job_id，明确匹配度主体是简历
- 仅调用粗排（纯规则计算），不触发 LLM 精排，响应 < 100ms
- 所有登录用户可调用

### 2.5 能力图谱页面改动

#### 匹配度获取

```typescript
// 选中简历 + 岗位后, 调用后端获取统一匹配分
const fetchMatchScore = async () => {
  if (!resumeId.value || !jobId.value) return
  matching.value = true
  try {
    // 入参: resume_id + job_id (匹配度主体是简历)
    const res: any = await matchApi.getScore(resumeId.value, jobId.value)
    const data = res.data
    matchScore.value = Math.round(data.total_score)
    dimensionScores.value = {
      skill: data.skill_score * 100,
      experience: data.experience_score * 100,
      education: data.education_score * 100,
      city: data.city_score * 100,
      salary: data.salary_score * 100,
      project: data.project_score * 100,
    }
  } finally {
    matching.value = false
  }
}

// 切换简历时重新计算
watch(resumeId, () => { if (jobId.value) fetchMatchScore() })
// 切换岗位时重新计算
watch(jobId, () => { if (resumeId.value) fetchMatchScore() })
```

### 2.6 投递管理改动

后端 `application.py` 匹配度计算改为调用 `match_service.coarse_rank()`：

```python
# 修改前
matched = [s for s in req_skills if s in resume_skills]
match_score = round(len(matched) / len(req_skills) * 100) if req_skills else 0

# 修改后 (使用统一匹配引擎)
scores = match_service.coarse_rank(resume, job)
match_score = round(scores["total"])
```

投递记录中的匹配度 = 投递时绑定的那份简历 vs 岗位的匹配度。

## 三、扩展想法

### 3.1 多简历匹配度对比

**场景**：用户上传了 Java 简历和 Python 简历，想看哪份简历更适合某个岗位。

**方案**：能力图谱页面顶部已有"选择简历"下拉框，切换简历后自动重新计算匹配度。用户可以快速切换对比。

**增强**：在简历列表页增加"匹配度预览"列，展示每份简历对选中岗位的匹配度，一目了然。

### 3.2 匹配度提升建议

**场景**：用户看到匹配度 65%，想知道怎么提升到 80%。

**方案**：在能力图谱底部展示 AI 生成的匹配度提升建议：

```
匹配度提升建议
├── 技能缺口: 缺少 Kubernetes (必须), 建议学习 K8s 基础
├── 经验差距: 岗位要求 5 年, 你有 3 年, 再积累 2 年
├── 学历匹配: 已满足 (本科及以上)
└── 城市匹配: 已满足 (北京)
```

**实现**：调用后端 LLM 生成建议，或前端根据六维度分数差值自动生成。

### 3.3 匹配度归因分析

**场景**：用户看到匹配度 85%，想知道这个分数是怎么算出来的。

**方案**：点击匹配度环形图，弹出归因面板：

```
匹配度归因 (85分)
├── 技能匹配  85/100  × 35% = 29.75 分
├── 经验匹配  90/100  × 20% = 18.00 分
├── 学历匹配 100/100  × 10% = 10.00 分
├── 城市匹配 100/100  × 10% = 10.00 分
├── 薪资匹配  80/100  × 10% =  8.00 分
└── 项目匹配  70/100  × 15% = 10.50 分
                            ─────────
                            合计 86.25 分
```

让匹配度透明可解释，用户信任度高。

### 3.4 岗位匹配度排序

**场景**：求职者在职位列表页，希望按匹配度排序，最匹配的排最前。

**方案**：职位列表页增加"按匹配度排序"选项，后端批量计算当前简历与每个岗位的匹配度，前端按分数降序排列。

### 3.5 匹配度变化追踪

**场景**：用户修改简历后（如新增技能），想看匹配度变化。

**方案**：简历更新后自动重新计算匹配度，并在能力图谱显示变化趋势：

```
岗位匹配度: 85% (↑5%)
  上次: 80% (2026-07-10)
  本次: 85% (2026-07-12)
  变化: +5% (新增了 Kubernetes 技能)
```

## 六、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 简历数据不完整 | 部分维度评分为 0 | 缺失维度给默认中等分 (0.5) |
| 粗排性能 | 查询慢 | 粗排为纯计算，无 LLM 调用，<100ms |
| 匹配度突变 | 用户困惑 | 正常现象，数值更合理 |
| 多简历切换频繁 | 重复请求 | 前端防抖 + 可选缓存 |

### 7.2 评分公式

```python
total = (
    skill_score    * 0.35   # 技能匹配度 [0,1]
  + exp_score      * 0.20   # 经验匹配度 [0,1]
  + edu_score      * 0.10   # 学历匹配度 [0,1]
  + city_score     * 0.10   # 城市匹配度 [0,1]
  + salary_score   * 0.10   # 薪资匹配度 [0,1]
  + proj_score     * 0.15   # 项目经历匹配度 [0,1]
) * 100
```

# 反馈系统重设计文档

> **文档编号**: ZPYT-FB-REDESIGN-V1
> **版本**: V1.0
> **编制日期**: 2026-08-03
> **适用版本**: 智聘云图 V1.1+

---

## 一、现状分析

### 1.1 现有架构

```
前端路由:
  /feedback          → Feedback.vue (独立路由, 不在任何 Layout 内)
  /admin/feedbacks   → Feedbacks.vue (AdminLayout 子路由)

后端 API:
  POST   /api/v1/feedback          提交反馈
  GET    /api/v1/feedback/my       我的反馈列表
  GET    /api/v1/admin/feedbacks   管理员反馈列表
  PUT    /api/v1/admin/feedbacks/{id}  管理员回复
```

### 1.2 核心问题

| # | 问题 | 影响 |
|---|------|------|
| 1 | `/feedback` 是独立路由，不在 `SeekerLayout` / `EmployerLayout` 内 | 用户点击侧边栏"意见反馈"后跳转到裸页面，丢失侧边栏导航，体验割裂 |
| 2 | 求职者端和企业端共用同一个 `Feedback.vue`，但路由不归属任何 Layout | 页面风格与工作台不一致，无法享受 Layout 的统一样式 |
| 3 | 管理员回复后，用户端无任何通知 | 用户不知道反馈已被处理，需要手动刷新查看 |
| 4 | 管理员反馈管理缺少统计概览 | 无法快速了解反馈整体情况（待处理数、各类型占比等） |
| 5 | 管理员反馈列表缺少关键词搜索 | 数据量大时难以定位特定反馈 |
| 6 | 反馈详情页交互粗糙（点击行打开弹窗） | 不符合常规管理后台操作习惯 |

---

## 二、设计方案

### 2.1 路由结构调整

**核心改动**: 将 `/feedback` 路由从独立路由改为各 Layout 的子路由。

```
前端路由 (修改后):
  /seeker/feedback       → Feedback.vue (SeekerLayout 子路由)
  /employer/feedback     → Feedback.vue (EmployerLayout 子路由)
  /admin/feedbacks       → Feedbacks.vue (AdminLayout 子路由, 不变)
```

**改动文件**:
- `router/index.ts`: 删除独立 `/feedback` 路由，在 Seeker 和 Employer 子路由中各添加 `feedback` 子路由
- `SeekerLayout.vue`: 菜单项 index 改为 `/seeker/feedback`
- `EmployerLayout.vue`: 菜单项 index 改为 `/employer/feedback`

### 2.2 求职者端 / 企业端反馈页面重构

**组件**: 复用 `Feedback.vue`，通过路由上下文自动适配角色。

#### 2.2.2 新增功能

| 功能 | 说明 |
|------|------|
| **快速提交区** | 表单始终可见（不再需要点击按钮弹出），降低提交门槛 |
| **反馈统计卡片** | 展示待处理/处理中/已解决的数量，让用户了解处理进度 |
| **卡片式列表** | 替代原有的边框列表，视觉更清晰，每条反馈独立卡片 |
| **管理员回复高亮** | 回复内容使用主题色背景突出显示，一目了然 |
| **反馈类型图标** | Bug 报告用红色图标，功能建议用蓝色图标，其他用灰色图标 |

#### 2.2.3 后端新增接口

```

```
返回当前用户各状态的反馈数量统计:
```json

  "data": {
    "pending": 3,
    "processing": 2,
    "resolved": 5,
    "total": 10
  }
}
```

#### 2.3.2 新增功能

| 功能 | 说明 |
|------|------|
| **统计概览卡片** | 顶部 4 个 KPI 卡片：总反馈数、待处理、处理中、已解决 |
| **关键词搜索** | 按标题/内容模糊搜索 |

#### 2.3.3 后端改动

**1) 管理员反馈列表接口增强** — 新增搜索和类型筛选参数:

```python
GET /api/v1/admin/feedbacks
参数:
  page: int
  size: int
  status: str | None        # 状态筛选 (不变)
  type: str | None          # 类型筛选 (新增)
```

返回数据新增用户信息:

```json
      "admin_reply": null,
      "created_at": "2026-08-01T14:30:00",
      "updated_at": "2026-08-01T14:30:00"
```

**2) 新增统计接口**:

```python
GET /api/v1/admin/feedbacks/stats
```
返回:
```json
{
  "code": 0,
  "data": {
    "total": 42,
    "pending": 8,
    "processing": 5,
    "resolved": 29
  }
```

**3) 管理员回复接口增强** — 新增 `notify` 参数:

```python
PUT /api/v1/admin/feedbacks/{id}
请求体:
{
  "status": "processing",
  "reply": "已修复, 请清除缓存后重试",
  "notify": true          # 是否发送站内消息通知 (新增, 默认 false)
}
```

当 `notify=true` 时，后端自动创建一条站内消息推送给提交反馈的用户:
```python
Message(
    user_id=feedback.user_id,
    type="system",
    title="您的反馈已处理",
    content=f"您提交的反馈「{feedback.title}」已被管理员处理，状态更新为：{status_label}。回复内容：{reply}"
)
```

**4) 用户端统计接口**:

```python
GET /api/v1/feedback/my-stats
```
返回当前用户各状态反馈数量。

## 四、交互流程

### 4.1 用户提交反馈流程

```
用户填写表单 → 点击提交 → 后端创建 Feedback 记录
    → 前端显示成功提示 → 表单清空 → 列表自动刷新 → 统计卡片更新
```

### 4.2 管理员处理反馈流程

```
管理员点击"处理" → 弹出详情弹窗
    → 选择处理状态 + 填写回复内容 + 勾选"通知用户"
    → 点击"确认处理"
    → 后端更新 Feedback 状态 + 回复内容
    → 若 notify=true → 创建 Message 记录 → WebSocket 推送给用户
    → 前端显示成功提示 → 列表自动刷新 → 统计卡片更新
```

### 4.3 用户收到反馈处理通知

```
管理员回复并勾选通知 → 用户消息中心收到"您的反馈已处理"消息
    → 用户点击消息 → 跳转到 /seeker/feedback 或 /employer/feedback
    → 查看管理员回复内容
```

## 五、UI 设计规范

### 5.1 配色方案

| 元素 | 颜色 | 说明 |
|------|------|------|
| 待处理标签 | `warning` (橙色) | 与现有系统一致 |
| 处理中标签 | `primary` (蓝色) | 与现有系统一致 |
| 已解决标签 | `success` (绿色) | 与现有系统一致 |
| Bug 报告图标 | `#f56c6c` (红色) | 醒目警示 |
| 功能建议图标 | `#1677ff` (蓝色) | 与主题色一致 |
| 其他类型图标 | `#909399` (灰色) | 低调 |
| 管理员回复背景 | `#f0f5ff` (浅蓝) | 与现有 Feedback.vue 一致 |

### 5.2 统计卡片样式

- 4 个卡片等宽排列，使用 `el-row` + `el-col :span="6"`
- 卡片内显示数字（大号字体）+ 标签（小号灰色字体）
- 待处理卡片数字使用橙色，处理中使用蓝色，已解决使用绿色

### 5.3 反馈卡片样式

- 每条反馈一个 `el-card`，`shadow="hover"`
- 卡片头部：类型图标 + 标题 + 状态标签
- 卡片主体：内容摘要（最多 3 行，超出省略）+ 提交时间
- 如有管理员回复，底部显示回复区域（浅蓝背景）

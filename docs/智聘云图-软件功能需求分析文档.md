## 第一章 引言

### 1.1 编写目的

本文档旨在全面、系统地定义"智聘云图"软件系统的功能需求与非功能需求，为后续的系统设计、开发实现、测试验证和验收交付提供明确的依据和参考。本文档面向的主要读者包括：项目经理、系统架构师、开发工程师、测试工程师、运维人员以及产品验收方。

### 1.2 适用范围

本文档适用于"智聘云图"V1.1+版本，覆盖求职者端、企业端、管理员端三大子系统的全部功能需求。文档中所定义的需求将作为后续各阶段工作的基线，任何需求的变更需经过正式的变更控制流程。

### 1.3 产品概述

智聘云图（ZhiPin YunTu）是一款基于文档智能解析的人岗匹配平台，采用B/S（Browser/Server）架构，通过大语言模型（LLM）自动解析简历文档，构建能力知识图谱，并运用六维度加权匹配引擎实现精准的人岗双向推荐。平台面向三类用户群体：求职者（Job Seeker）、企业招聘方（Employer）、平台管理员（Admin），提供了从简历上传、职位发布、智能匹配到面试邀请的全流程闭环服务。

### 1.4 定义与缩写

| 术语 | 全称 | 说明 |
|------|------|------|
| LLM | Large Language Model | 大语言模型，本文中指豆包大模型 |

| RBAC | Role-Based Access Control | 基于角色的访问控制模型 |
| JWT | JSON Web Token | 用于身份认证的令牌标准 |

| QPS | Queries Per Second | 每秒查询次数 |

## 第二章 项目背景与目标

### 2.1 项目背景

当前人才招聘市场面临以下核心痛点：

**痛点一：简历筛选效率低下。** 传统招聘流程中，企业HR需要人工阅读大量简历，平均每份简历的初步筛选耗时约30秒至2分钟。对于热门岗位，HR可能需要处理数千份简历，单岗位筛选周期长达5-7天，严重影响招聘效率。

**痛点二：人岗匹配精准度不足。** 传统招聘平台主要依赖关键词搜索和简单的标签匹配，缺乏对简历语义信息的深度理解和对岗位需求的全面评估。HR往往需要多次搜索和筛选才能找到合适的候选人，匹配精准度通常低于40%。

**痛点三：简历信息结构不统一。** 求职者简历格式各异（PDF、DOC、DOCX、图片等），信息组织结构各不相同，HR需要花费大量时间从不同格式的简历中提取关键信息，造成严重的人力浪费。

**痛点四：决策依据不充分。** 在多个候选人之间进行取舍时，HR缺乏量化的比较依据，往往依赖主观经验和直觉，难以向用人部门提供客观的决策理由。

**痛点五：信息孤岛问题。** 求职者和企业之间的信息不对称严重，求职者难以了解岗位的真实需求，企业也难以全面了解候选人的能力结构。

### 2.2 项目目标

基于上述痛点，智聘云图项目设定以下核心目标：

**核心目标一：文档智能解析。** 支持PDF、DOC、DOCX格式简历和职位描述文档的自动上传与AI智能解析，将非结构化文档自动转换为结构化数据，解析准确率不低于90%。

**核心目标二：能力图谱可视化。** 基于知识图谱技术，构建求职者个人能力图谱和岗位能力图谱，实现技能结构的可视化展示，帮助用户直观了解能力分布与匹配缺口。

**核心目标三：精准双向匹配。** 构建六维度加权匹配引擎，结合大语言模型精排，实现求职者→职位的精准推荐和企业→候选人的智能推荐，Top10命中率不低于75%。

**核心目标四：全流程闭环服务。** 覆盖从简历上传、职位发布、智能匹配、投递管理、面试邀请到录用决策的全招聘流程，提供一站式的招聘服务体验。

**核心目标五：多角色协同工作。** 提供求职者、企业、管理员三端独立工作台，实现角色隔离、数据互通、权限分级的协同工作模式。

**核心目标六：商业化闭环。** 构建VIP会员+单次付费双轨计费体系，模拟真实的支付流程，实现商业价值的闭环验证。

### 2.3 目标用户群体

本系统面向三类核心用户群体：

| 用户群体 | 典型用户 | 用户规模预估 | 核心诉求 |
|----------|---------|-------------|----------|
| 求职者 | 高校毕业生、社会求职人员 | 10万+ | 快速制作简历、精准匹配职位、了解自身能力结构 |
| 企业招聘方 | HR、招聘经理、用人部门负责人 | 5000+ | 高效筛选简历、精准推荐候选人、管理招聘流程 |
| 平台管理员 | 运营人员、系统管理员 | 50+ | 平台运营监控、用户管理、数据统计分析 |

## 第三章 用户角色分析

### 3.1 角色定义

系统采用基于角色的访问控制（RBAC）模型，定义三个核心角色：

| 角色标识 | 角色名称 | 权限等级 | 工作台前缀 |
|---------|---------|---------|-----------|
| ROLE_SEEKER | 求职者 | 低 | /seeker |
| ROLE_EMPLOYER | 企业招聘方 | 中 | /employer |
| ROLE_ADMIN | 平台管理员 | 高 | /admin |

### 3.2 角色职责分析

#### 3.2.1 求职者角色分析

**用户画像**：求职者通常是正在寻找工作机会的各类人才，包括应届毕业生、社会从业人员和转行求职者。他们的核心诉求是快速了解市场需求、展示自身能力、获得面试机会。

**核心职责**：
- 上传个人简历，授权系统进行AI智能解析
- 浏览和搜索平台上的职位信息
- 查看系统推荐的匹配职位
- 投递感兴趣的职位并跟踪投递状态
- 管理个人收藏的职位
- 通过能力图谱了解自身技能结构
- 接收并处理企业的面试邀请
- 管理个人账户信息和密码

**使用场景**：
- 场景A：应届毕业生上传简历，通过AI推荐快速找到匹配的初级岗位
- 场景B：在职人员更新简历，查看能力图谱发现技能短板，有针对性地提升
- 场景C：求职者接收面试邀请，确认面试时间和地点

#### 3.2.2 企业招聘方角色分析

**用户画像**：企业招聘方通常是企业的HR或招聘负责人，他们的核心诉求是快速找到符合岗位要求的候选人，有效管理招聘流程。

**核心职责**：
- 发布和管理招聘职位（含AI智能解析JD）
- 查看系统推荐的匹配候选人
- 管理求职者投递记录
- 发送面试邀请给合适的候选人
- 管理企业资质认证
- 管理企业账户信息和密码
- 订阅VIP会员服务

**使用场景**：
- 场景A：HR发布新岗位，上传JD文档由AI自动解析并填充信息
- 场景B：HR查看系统推荐的候选人列表，根据匹配度排序筛选
- 场景C：HR对合适的候选人发送面试邀请，跟踪邀请状态

#### 3.2.3 平台管理员角色分析

**用户画像**：平台管理员是系统运营的核心人员，关注平台的健康度、安全性和商业价值。

**核心职责**：
- 监控平台运行状态和核心业务指标
- 管理全平台用户（启用/禁用/角色修改）
- 管理全平台简历和职位数据
- 审核企业资质认证申请
- 查看操作日志和审计记录
- 管理VIP会员和查看营收数据
- 处理用户反馈

### 5.2 数据流分析

**核心数据流一：简历全生命周期**
```
用户上传简历文件 → 文件存储 → 文本提取 → LLM解析 → 结构化数据入库 → 技能关联入库 → 图谱构建 → AI分析
```

**核心数据流二：匹配推荐全流程**
```
用户发起匹配请求 → 查询匹配缓存 → 如未命中则执行召回 → 规则粗排 → LLM精排 → 生成匹配理由 → 存匹配记录 → 返回推荐结果
```

**核心数据流三：投递闭环**
```
求职者投递 → 创建投递记录 → 通知企业 → 企业查看/更新状态 → 面试邀请/不合适 → 通知求职者 → 求职者响应
```

### 5.3 数据安全需求

| 安全需求 | 说明 | 优先级 |
|---------|------|--------|
| 密码加密存储 | 使用bcrypt算法加密存储密码，不可逆 | 高 |
| 敏感信息脱敏 | 手机号、邮箱等敏感信息在日志中脱敏处理 | 高 |
| 数据备份 | 数据库每日自动备份，保留7天 | 高 |
| 数据隔离 | 不同角色用户数据严格隔离，防止IDOR攻击 | 高 |
| SQL注入防护 | 使用ORM参数化查询，禁止拼接SQL | 高 |

## 第七章 用例分析

### 7.1 求职者用例图

**用例UC-01：上传简历并获取AI解析**
- 参与者：求职者
- 前置条件：用户已登录（ROLE_SEEKER）
- 基本流程：
  1. 用户进入简历上传页面
  2. 选择简历文件（PDF/DOC/DOCX）
  3. 系统校验文件格式和大小
  4. 系统上传文件并触发AI解析
  5. 系统显示解析进度
  6. 解析完成后展示结构化结果
  7. 系统自动触发AI智能分析
  8. 展示完整度评分和改进建议
- 后置条件：简历数据已入库，技能图谱已构建
- 备选流程：解析失败时，系统展示错误信息并允许重新上传

**用例UC-02：查看职位推荐**
- 参与者：求职者
- 前置条件：用户已登录，至少有一份已解析简历
- 基本流程：
  1. 用户进入职位推荐页面
  2. 系统基于最新简历计算匹配度
  3. 展示推荐职位列表（含匹配度百分比）
  4. 用户可查看每个职位的六维度评分明细
  5. 用户可查看AI生成的匹配理由
- 后置条件：无
- 备选流程：配额不足时提示升级VIP

**用例UC-03：投递职位**
- 参与者：求职者
- 前置条件：用户已登录，至少有一份简历
- 基本流程：
  1. 用户在职位详情页点击"投递"按钮
  2. 系统校验是否已投递过（防重复投递）
  3. 系统自动关联最新简历
  4. 创建投递记录（状态=待处理）
  5. 通知企业用户
  6. 返回投递成功提示
- 后置条件：投递记录已创建，企业端收到通知

### 7.2 企业用例图

**用例UC-04：发布职位**
- 参与者：企业用户
- 前置条件：用户已登录（ROLE_EMPLOYER）
- 基本流程：
  1. 用户进入职位发布页面
  2. 填写职位基本信息（标题、薪资、城市、学历、经验）

  4. 添加技能要求（设置必须/优先）
  5. 点击发布
  6. 系统校验并创建职位
- 后置条件：职位已发布（状态=招聘中）

**用例UC-05：查看候选人推荐**
- 参与者：企业用户
- 前置条件：用户已登录，至少有一个已发布职位
- 基本流程：
  1. 用户选择目标职位
  2. 系统基于职位要求计算匹配度
  3. 展示候选人列表（含匹配度百分比）
  4. 用户可查看六维度评分明细
  5. 用户可查看匹配理由
  6. 用户可查看简历详情或发送面试邀请
- 后置条件：无

**用例UC-06：处理投递**
- 参与者：企业用户
- 前置条件：用户已登录，有收到投递
- 基本流程：
  1. 用户进入投递管理页面
  2. 查看投递列表（按职位/状态筛选）
  3. 点击投递记录查看详情
  4. 更新投递状态（已查看/面试邀请/不合适/已录用）
  5. 如选择面试邀请，跳转面试邀请创建页面
- 后置条件：投递状态已更新，通知求职者

### 7.3 管理员用例图

**用例UC-07：监控平台数据**
- 参与者：管理员
- 前置条件：管理员已登录
- 基本流程：
  1. 管理员进入数据指挥中心
  2. 查看KPI指标卡（总用户数、简历数、职位数、投递数）
  3. 查看各数据图表（用户增长、技能词云、投递漏斗等）
  4. 查看实时日志流
- 后置条件：无

**用例UC-08：管理用户**
- 参与者：管理员
- 前置条件：管理员已登录
- 基本流程：
  1. 管理员进入用户管理页面
  2. 查看用户列表（可按角色/状态筛选）
  3. 选择用户进行启用/禁用操作
  4. 或修改用户角色
  5. 或导出用户数据为CSV
- 后置条件：用户状态已变更

## 第十章 需求风险分析

### 10.1 技术风险

| 风险编号 | 风险描述 | 影响程度 | 发生概率 | 应对措施 |
|---------|---------|---------|---------|---------|
| R-001 | ARK API调用超时或失败 | 高 | 中 | 实现重试机制（指数退避），设置合理超时时间，前端友好提示 |
| R-002 | LLM解析结果不稳定 | 中 | 中 | 使用低温度参数（0.1），强制JSON Schema输出，后处理校验修复 |
| R-003 | 数据库性能瓶颈 | 高 | 低 | 优化索引，使用Redis缓存，selectinload预加载 |
| R-004 | 文件上传安全漏洞 | 高 | 低 | magic number校验，文件大小限制，MD5重命名存储 |

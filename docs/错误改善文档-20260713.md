## 二、🔴 严重问题（已修复）

### 2.1 `admin/vip/revenue` 接口 500 错误

**文件**: `backend/app/api/v1/vip.py`  
**行号**: 272-338  

**问题**: `admin_revenue()` 函数内使用了 `func` 和 `select`，但未导入这两个符号。

```python
# ❌ 修复前
from app.models.payment import PaymentRecord
total_revenue = db.query(func.sum(PaymentRecord.amount))...  # func 未定义
```

**修复**: 添加 `from sqlalchemy import func, select`，同时将所有 `db.execute(X).where(...)` 错误语法改为 `select(func.coalesce(...)).where(...)`。

```python
# ✅ 修复后
from sqlalchemy import func, select
from app.models.payment import PaymentRecord
total_revenue = db.execute(
    select(func.coalesce(func.sum(PaymentRecord.amount), 0))
    .where(PaymentRecord.status == "success")
).scalar() or 0
```

### 2.2 `PUT /resumes/{id}` 编辑简历时 `db.query()` 报错

**文件**: `backend/app/api/v1/resume.py`  
**行号**: 230  

**问题**: 使用 SQLAlchemy 1.x 遗留 API `db.query().filter().delete()`，在 SQLAlchemy 2.0+ 中已移除。

```python
# ❌ 修复前
db.query(ResumeSkill).filter(ResumeSkill.resume_id == resume_id).delete()
```

**修复**: 改用 SQLAlchemy 2.0 的 `delete()` 构造器。

```python
# ✅ 修复后
from sqlalchemy import select, delete
db.execute(delete(ResumeSkill).where(ResumeSkill.resume_id == resume_id))
```

### 2.3 `job_service.create()` 中 `parsed` 变量可能未定义

**文件**: `backend/app/services/job_service.py`  
**行号**: 43-75  

**问题**: 当 `parse_text` 为纯空格字符串时，`parse_text and parse_text.strip()` 为 `False`，`parsed` 未定义。但后续 `if parse_text:` 为 `True`，访问 `parsed` 抛出 `UnboundLocalError`。

```python
# ❌ 修复前
parse_text = data.pop("parse_text", None)
if parse_text and parse_text.strip():
    parsed, _ = doc_parser.parse_job(parse_text)
else:
    requirements = ...
# ...
if parse_text:  # parse_text 非空但 strip() 为空 → parsed 未定义
    job.raw_parse_json = json.dumps(parsed, ...)
```

**修复**: 在分支前初始化 `parsed = None`。

```python
# ✅ 修复后
parse_text = data.pop("parse_text", None)
parsed = None
if parse_text and parse_text.strip():
    parsed, _ = doc_parser.parse_job(parse_text)
```

### 3.4 分页查询全量加载计算 total

**文件**: `backend/app/api/v1/match.py:254`、`backend/app/services/admin_service.py:338`  

**问题**: 使用 `total = len(list(db.execute(stmt).scalars()))` 将全部数据加载到内存再计数，数据量大时会导致 OOM。

```python
# ❌ 修复前
total = len(list(db.execute(stmt).scalars()))  # 全量加载到内存
```

**修复**: 使用 `SELECT COUNT(*)` 子查询在数据库端计数。

```python
# ✅ 修复后
count_stmt = select(func.count()).select_from(stmt.subquery())
total = db.execute(count_stmt).scalar() or 0
```

## 五、经验教训

### 5.1 前后端字段名必须严格对齐
后端修改响应字段名后，必须同步更新所有前端使用该字段的页面。建议使用 TypeScript 的接口类型约束后端返回结构，编译时即可发现字段名不匹配。

### 5.2 SQLAlchemy 2.0 迁移注意事项
- `db.query()` 已废弃，统一使用 `db.execute(select(...))`
- `db.execute()` 返回 `Result` 对象，不能链式调用 `.where()`，必须在 `select()` 内用 `.where()`
- 函数内使用 `func`/`select` 等符号时需确保导入

### 5.3 函数内局部导入的隐患
`admin_revenue()` 函数使用了 `func` 和 `select` 但未导入，因为在其他函数中它们是局部导入的。建议统一在文件顶部导入。

### 5.4 变量未初始化的风险
Python 的 `UnboundLocalError` 发生在条件分支中变量可能未定义的情况下。对于在条件分支中赋值的变量，应在分支前初始化为 `None`。

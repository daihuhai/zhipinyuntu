## 三、PII 脱敏处理

### 3.1 脱敏工具

新建 `backend/app/utils/mask.py`:
- `mask_phone`: `13812345678` → `138****5678`
- `mask_email`: `zhangsan@qq.com` → `z***@qq.com`

### 3.2 应用范围

| 接口 | 场景 | 脱敏字段 |
|------|------|---------|
| `GET /resumes/{id}` | 企业查看简历详情 | phone, email |
| `GET /applications/employer` | 企业查看投递列表 | phone, email |
| `GET /applications/job/{id}` | 企业查看职位投递 | phone, email |

**脱敏规则**: 仅企业角色 (ROLE_EMPLOYER) 查看时脱敏, 求职者本人和管理员不脱敏。

## 四、安全漏洞修复 (IDOR 越权)

安全审查发现 4 处 IDOR (Insecure Direct Object Reference) 越权漏洞, 可导致企业遍历 ID 查看其他企业的投递简历 (含 PII), 已全部修复:

| 接口 | 漏洞 | 修复 |
|------|------|------|
| `GET /applications/job/{job_id}` | 未校验职位归属, 任意企业可查任意职位投递 | 增加归属校验 + PII 脱敏 |
| `POST /applications/{id}/status` | 未校验投递归属, 任意企业可改任意投递状态 | 增加 job 归属校验 |
| `POST /applications/batch/status` | 批量更新未校验归属 | 预查本企业 job_id 集合, 跳过非本企业记录 |
| `GET /match/job/{id}/resumes` | 未校验职位归属, 任意企业可查任意职位候选人 | 增加 job 归属校验 |

**涉及文件**:
- `backend/app/api/v1/application.py`
- `backend/app/api/v1/match.py`

## 五、查看原文件 404 修复

**根因** (三重问题):
1. Vite 仅代理 `/api`, 未代理 `/uploads`, 前端访问 `/uploads/xxx.pdf` 时 dev server 返回 404
2. 数据库 44 条种子数据的 `doc_url` 缺少前导 `/`, 前端 `window.open` 打开相对路径
3. 种子数据 doc_url 指向虚假路径, 实际文件不存在

**修复**:
- `vite.config.ts` 新增 `/uploads` 代理到后端 8001
- `resume.py` `get_resume_file` 规范化 doc_url, 确保以 `/uploads/` 开头
- 数据库 44 条种子数据 doc_url 批量更新为真实 PDF 文件

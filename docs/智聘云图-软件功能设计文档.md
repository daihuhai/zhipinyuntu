## 第一章 引言

### 1.1 编写目的

本文档是"智聘云图"软件系统的详细功能设计文档，旨在对系统需求分析阶段确定的功能需求进行系统化的技术设计，为后续的编码实现、系统测试和部署运维提供详细的技术指导。本文档面向系统架构师、开发工程师、测试工程师和运维人员。

### 1.2 适用范围

本文档覆盖"智聘云图"V1.1+版本的全部功能模块，包括：用户认证、简历管理、职位管理、匹配推荐、知识图谱、投递管理、面试邀请、消息通信、VIP计费、企业管理、管理员后台、企业资质认证、职位订阅和用户反馈等14个功能模块的设计方案。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 高内聚低耦合 | 各功能模块独立封装，模块间通过API通信，减少相互依赖 |
| 前后端分离 | 前端Vue3负责UI渲染，后端FastAPI负责业务逻辑和数据访问 |
| 安全性优先 | 从设计阶段即考虑安全防护，包括身份认证、权限校验、数据隔离 |
| 可扩展性 | 预留扩展点，支持未来功能迭代和水平扩展 |
| 容错降级 | 关键依赖（Redis、Neo4j、AI服务）不可用时自动降级 |

### 3.1 用户认证模块（M-01）

#### 3.1.1 注册流程设计

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 选择角色   │───▶│ 填写表单   │───▶│ 后端校验   │───▶│ 创建用户   │
│ 求职者/企业 │    │ 用户名/密码│    │ 唯一性/强度│    │ bcrypt加密 │
└──────────┘    └──────────┘    └──────────┘    └─────┬────┘
                                                       │
                                              ┌────────▼──────┐
                                              │ 签发JWT双令牌   │
                                              │ access+refresh │
                                              └────────┬──────┘
                                                       │
                                              ┌────────▼──────┐
                                              │ 返回用户信息+令牌│
                                              └───────────────┘
```

**密码校验规则**：长度≥8位，必须包含字母和数字，支持特殊字符。

**速率限制**：注册接口3次/分钟/IP，由slowapi的`@limiter.limit("3/minute")`装饰器实现。

#### 3.1.2 JWT认证设计

**令牌结构**：

```python
# Access Token (2小时有效期)
{
  "sub": user_id,       # 用户ID
  "role": "ROLE_SEEKER", # 角色标识
  "exp": timestamp,      # 过期时间
  "iat": timestamp,      # 签发时间
  "type": "access"       # 令牌类型
}

# Refresh Token (7天有效期)
{
  "sub": user_id,
  "exp": timestamp,
  "type": "refresh"
}
```

**认证流程**：

```
客户端请求 → 携带Authorization: Bearer <access_token>
  → 后端get_current_user依赖注入
    → decode_token验证JWT签名和有效期
      → 从token中提取user_id和role
        → 查询数据库获取用户完整信息
          → 注入到请求处理函数

客户端请求刷新 → POST /auth/refresh 携带refresh_token
  → 后端验证refresh_token
    → 签发新的access_token和refresh_token
```

#### 3.1.3 权限校验设计

**路由守卫实现**（前端）：

```typescript
// router/index.ts
router.beforeEach((to, from, next) => {
  if (to.meta.public) return next()  // 公开页面放行
  
  const userInfo = JSON.parse(localStorage.getItem('user_info') || '{}')
  if (!userInfo.role) return next('/login')  // 未登录跳转登录页
  
  const rolePrefixMap = {
    ROLE_SEEKER: '/seeker',
    ROLE_EMPLOYER: '/employer',
    ROLE_ADMIN: '/admin',
  }
  const expectedPrefix = rolePrefixMap[userInfo.role]
  
  if (to.path.startsWith(expectedPrefix)) {
    next()  // 角色匹配，放行
  } else {
    next(expectedPrefix)  // 越权访问，重定向到自有工作台
  }
})
```

**接口鉴权实现**（后端）：

```python
# core/deps.py
def require_role(*roles: str):
    """角色校验依赖注入"""
    async def role_checker(current_user: SysUser = Depends(get_current_user)):
        if current_user.role not in roles:
            raise HTTPException(status_code=403, detail="权限不足")
        return current_user
    return role_checker

# 使用示例
@router.get("/admin/users")
async def get_users(
    current_user = Depends(require_role("ROLE_ADMIN"))
):
    ...
```

### 3.3 匹配推荐模块（M-04）

#### 3.3.1 六维度匹配算法设计

**匹配总分计算公式**：

```
MatchScore = Σ(weight_i × score_i) × 100
```

其中 weight_i 为各维度权重，score_i 为各维度得分（0-1范围）。

**各维度算法**：

**维度1：技能匹配（weight=0.40）**

```
matched_skills = count(required_skills ∩ resume_skills)
required_skills_count = count(required_skills)
// 必须技能权重1.0，优先技能权重0.6
required_hit_score = sum(1.0 for hit in must_hits) + sum(0.6 for hit in prefer_hits)
required_total_score = count(must_skills) * 1.0 + count(prefer_skills) * 0.6
skill_score = required_hit_score / required_total_score if required_total_score > 0 else 0
```

**技能别名归一化表**：

```python
SKILL_ALIASES = {
    "java": ["java", "java语言", "java开发", "jdk", "java8"],
    "python": ["python", "python3", "py", "python开发"],
    "mysql": ["mysql", "sql", "数据库", "关系型数据库"],
    "vue": ["vue", "vue.js", "vuejs", "vue2", "vue3"],
    "react": ["react", "react.js", "reactjs", "react native"],
    "docker": ["docker", "容器", "容器化", "docker compose"],
    "kubernetes": ["kubernetes", "k8s", "k3s"],
    "spring": ["spring", "springboot", "spring-boot", "spring cloud"],
}
```

**维度2：经验匹配（weight=0.20）**

```
if resume_work_years >= required_experience_years:
    exp_score = 1.0
else:
    exp_score = resume_work_years / required_experience_years * 0.8
```

**维度3：学历匹配（weight=0.15）**

```
EDUCATION_LEVEL = {"博士": 5, "硕士": 4, "本科": 3, "大专": 2, "其他": 1}
if EDUCATION_LEVEL[resume_education] >= EDUCATION_LEVEL[required_education]:
    edu_score = 1.0
else:

```

**维度4：城市匹配（weight=0.10）**

```
if job_city in resume_intention_cities:
    city_score = 1.0
elif job_city == resume_current_city:
    city_score = 0.8
else:
    city_score = 0.3
```

**维度5：薪资匹配（weight=0.10）**

```
if resume_salary_min <= job_salary_max and resume_salary_max >= job_salary_min:
    # 区间有重叠
    overlap = min(resume_salary_max, job_salary_max) - max(resume_salary_min, job_salary_min)
    salary_span = max(resume_salary_max - resume_salary_min, job_salary_max - job_salary_min)
    salary_score = overlap / salary_span if salary_span > 0 else 0.5
else:
    salary_score = 0.2
```

**维度6：项目匹配（weight=0.05）**

```
project_skills = all_tech_stack_from_projects
matched_project_skills = count(required_skills ∩ project_skills)
project_score = min(matched_project_skills / max(count(required_skills), 1), 1.0)
```

```python
# 批量精排：将4个候选人合并为1次LLM调用
def build_batch_rerank_messages(resume, candidates, job):
    """构建批量重排消息"""
    candidates_text = "\n---\n".join([
        f"候选人{i+1}: {c['name']}, {c['work_years']}年经验, "
        f"技能: {', '.join(c['skills'])}, 学历: {c['education']}, "
        f"当前城市: {c['city']}, 期望薪资: {c['salary_min']}-{c['salary_max']}"
        for i, c in enumerate(candidates)
    ])
    
    prompt = f"""作为资深招聘专家，请对以下候选人进行匹配度评估。

职位：{job['title']}
要求技能：{', '.join(job['required_skills'])}
工作城市：{job['work_city']}
学历要求：{job['education_required']}
经验要求：{job['experience_required']}年
薪资范围：{job['salary_min']}-{job['salary_max']}

候选人列表：
{candidates_text}

请输出JSON格式的评估结果，包含每个候选人的综合匹配分(0-100)和匹配理由。"""
    return prompt
```
